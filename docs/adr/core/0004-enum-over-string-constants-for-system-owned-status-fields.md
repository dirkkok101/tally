# ADR-CORE-0004: Enum Over String Constants for System-Owned Status Fields

> Generated from the lex graph. Do not edit this file as source of truth; update graph entities and re-export.

**Status:** Accepted
**Origin:** Capstone convention, adopted by Identity (ADR-0004), adopted by Actions on independent merit.

## Context

System-owned status, kind, and mode fields appear throughout the Actions domain, such as ActionStatus, WorkflowStateType, ConsultationStatus, import modes, and lifecycle states. These fields need type safety, exhaustive switch handling, and consistent serialization between C# and PostgreSQL. Tenant-configurable catalogues such as Action Types, RCA Methods, Deadline Types, or other admin-owned lookup data are explicitly outside this ADR and must follow ADR-CORE-0028 instead.

## Decision

System-owned finite status, kind, and mode fields use C# enums with HasConversion<string>() in EF Core. Enum values are stored as PascalCase strings in PostgreSQL, EnumDTO is used on API contracts for true enum roundtrip, and new code must not introduce const string sets for fields that are truly system-owned finite states. User-configurable lookup/configuration values must not be modeled as enums merely because they appear in dropdowns; they require an owning admin module or immutable platform-template design.

## Consequences

Compile-time safety is retained for system-owned states without freezing tenant-configurable configuration into code. Adding a new enum member still requires coordinated deployment and append-only ordinal discipline when EnumDTO is exposed. Admin-owned catalogues carry a larger implementation surface, but clean-system commissioning remains honest and browser E2E can configure tenant data through the Portal.
