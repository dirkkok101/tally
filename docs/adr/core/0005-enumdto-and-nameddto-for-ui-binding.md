# ADR-CORE-0005: EnumDTO and NamedDTO for UI Binding

> Generated from the lex graph. Do not edit this file as source of truth; update graph entities and re-export.

**Status:** Accepted
**Origin:** Capstone convention, adopted by Identity (ADR-0005), adopted by Actions for roundtrip simplification.

## Context

Admin UIs have dropdown fields bound to both system enums and foreign-key/catalogue references. Each dropdown needs an identifier and display name, but the identifier semantics differ: true enums use stable system-owned ordinals, while tenant-configurable catalogues use database ids and/or stable codes from the owning admin module.

## Decision

DTOs use standard wrapper types for dropdown-bindable fields. EnumDTO { Id: int, Name: string } is only for true system-owned enum fields. NamedDTO { Id: Guid, Name: string, Description?: string } is for FK references. User-configurable catalogues may also expose stable string Code fields where downstream contracts require human-readable integration keys. Entity mappers cast EnumDTO only for true enums; commands validate catalogue ids/codes against active tenant records before persistence.

## Consequences

Zero-transformation roundtrip remains the default for dropdowns, but dropdown shape no longer implies enum ownership. Enum member ordering remains part of the wire contract only for true enums. Configurable lookup data gets explicit owner modules, lookup endpoints, and validation instead of local enum aliases or compatibility mappers.
