# ADR-CORE-0022: EntityMapper Pure Transformer with Bulk Support

> Generated from the lex graph. Do not edit this file as source of truth; update graph entities and re-export.

**Status:** Accepted
**Origin:** Capstone convention, adopted by Identity (ADR-0025), adopted by Actions with confirmed bulk requirement.

## Context

Entity creation and update require mapping DTO fields to entity properties. This mapping can live in the command, in a static extension method, or in a dedicated mapper class. Additionally, Actions has confirmed bulk Excel import/export functionality — the mapper must handle batch operations efficiently.

## Decision

**EntityMapper is a DI-registered class that performs focused DTO-to-entity transformation.** It maps fields and resolves entities for updates — nothing else. Batch signature is primary; single-DTO is a convenience overload.

**Responsibility boundary:**

| EntityMapper (pure transformer) | Command (business logic) |
|--------------------------------|------------------------|
| Field mapping (scalar, enum cast, FK read) | Protection checks (system entities) |
| Audit field stamping (Created/Updated) | Uniqueness checks |
| Translation handling (AddOrUpdateEntityTranslation) | Child diffing (add/update/delete sets) |
| Create vs update detection (Guid.Empty) | Cross-entity operations |
| Entity resolution (FindAsync for updates) | SaveChangesAsync |
| Return EntityMapperResult<T> | Post-save side effects |

**Signatures:**
```csharp
// Batch (primary)
Task<EntityMapperResult<T>> MapAsync(
    List<SaveRequest> dtoList, Guid userId,
    Guid requestLanguageId, Guid defaultLanguageId,
    CancellationToken ct, ActionsDbContext? db = null)

// Single (convenience — wraps in list, delegates to batch)
Task<EntityMapperResult<T>> MapAsync(
    SaveRequest dto, Guid userId,
    Guid requestLanguageId, Guid defaultLanguageId,
    CancellationToken ct, ActionsDbContext? db = null)
```

**`EntityMapperResult<T>`:**
```csharp
public class EntityMapperResult<T> {
    public IList<T> NewItems { get; init; } = [];
    public IList<T> UpdatedItems { get; init; } = [];
    public IList<T> DeletedItems { get; init; } = [];
}
```

**Rules:**
- Performs only `FindAsync` for entity resolution on updates — does not query for business rules or validation
- Never contains business logic, guards, or cross-entity operations
- Never calls `SaveChangesAsync`
- Immutable fields set on create, intentionally omitted on update (with comment)
- Optional `ActionsDbContext? db` parameter for shared transaction contexts (required for `FindAsync` — this makes the mapper "focused" not "pure" in the strict sense)

**DeletedItems:** For child entity diffing, the Command computes deleted sets and populates `DeletedItems`. The mapper only produces `NewItems` and `UpdatedItems`.

## Consequences

**Positive:**
- Focused transformation is independently testable (mock DbContext for `FindAsync`)
- Batch-primary signature directly supports Excel bulk import
- Single-DTO overload adds zero overhead for standard CRUD
- Clear responsibility boundary — mapper bugs are mapping bugs, not business logic bugs

**Negative:**
- `EntityMapperResult` with list properties is slightly over-engineered for single-entity saves
- `mapResult.NewItems.FirstOrDefault() ?? mapResult.UpdatedItems.First()` pattern in endpoints

**Trade-off accepted:** Bulk Excel import is a confirmed requirement. The batch-primary design is justified, not speculative.
