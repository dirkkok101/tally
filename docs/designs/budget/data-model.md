- result BudgetInsightEvidence: {planState: BoundRevision|NoBudgetPlan|NoActiveBudgetPlanRevision, planRevisionDetail?, budgetPosition?, datedActualMembers[], ledgerBudgetActualTotal, ledgerSnapshotId, ledgerStoreGenerationFingerprint, ledgerContractVersion, categoryContractVersion, calculationSchemaVersion?, evidenceBindingFingerprint}

Unsupported versions fail before financial processing.

## BudgetOperationContracts

**Ref Code:** DM-BUDGET-OPERATION-CONTRACTS

Concrete versioned request, result, authority, idempotency, limit, and stable error contracts for the six Public Budget Operations plus shared contract discovery.

### Schema

All operations use the common Public Budget Operation envelope, owner or delegated authority metadata, versioned request/result/error fingerprints, deterministic limits, stable exit categories, and metadata-only diagnostics.

budget.plan.draft.create input {period, entries[], reason}; mutating, actor and idempotency required; result immutable Draft revision.
budget.plan.revision.get input {revisionId}; result BudgetPlanRevisionDetail containing immutable revision payload plus current supplemental CategoryLifecycleEvidence.
budget.plan.revision.list input {period?, status?, limit}; result bounded metadata-first revision history.
budget.plan.revision.activate input {revisionId, reason}; mutating, actor and idempotency required; result activated revision and supersession evidence.
budget.position.get input {period:{year,month,currencyCode:ZAR}, revisionId?}; selected revision must belong to the supplied period/currency or BUDGET-REVISION-PERIOD-MISMATCH is returned before LEDGER; result BudgetPosition or explicit NoActiveBudgetPlanRevision.
budget.insights.evidence.get input {budgetPeriod, revisionId?, memberLimit}; read-only; result BudgetInsightEvidence containing explicit planState, optional immutable revision detail and BudgetPosition, bounded dated actual members, exact public LEDGER budget-actual total, shared snapshot identity and generation, optional calculation schema, and binding fingerprint. BoundRevision reuses one complete snapshot for the canonical position and members. NoBudgetPlan and NoActiveBudgetPlanRevision return no plan or position but retain the complete snapshot members and exact total without invoking the calculator. Unprovable binding returns BUDGET-SOURCE-STATE-CHANGED and a limit breach returns BUDGET-RESOURCE-LIMIT before partial output.

Unknown fields, unsupported versions, invalid periods, unsafe amounts, authority failures, incompatibility, integrity failures, downstream failures, and resource limits are stable typed outcomes. No operation starts a daemon, uses network access, reads private LEDGER storage, emits financial payloads outside its business result, or grants INSIGHTS mutation authority.
