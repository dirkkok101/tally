# Six explicit BUDGET operations from one registry

## Description

Make every v1 plan and position capability discoverable without HTTP, generic CRUD, or hidden actions.

## Decision

Expose budget.plan.draft.create, budget.plan.revision.get, budget.plan.revision.list, budget.plan.revision.activate, budget.position.get, and the read-only budget.insights.evidence.get under tally budget. Reuse system.schema.list/show for Discover Contract. One explicitly registered descriptor registry generates dispatch, help, machine schemas, compatibility metadata, limits, errors, authority, mutability, idempotency metadata, and process envelopes. Complex input uses explicit stdin or file JSON and every invocation emits one business envelope.

## Rationale

Each lifecycle or read intent needs a stable schema and authority surface. The A3 spike established that coherent INSIGHTS evidence is a distinct producer intent: it must bind the canonical position and dated members inside one BUDGET operation and cannot be represented by two safe independent calls. Shared discovery remains separate, and no generic execute or HTTP facade is introduced.

## Alternatives

A: generic budget.plan.execute with an action field, rejected as a shallow facade. B: HTTP Save/Get/Grid/Delete endpoints, rejected because the module has no network or UI. C: six explicit operations plus shared registry discovery, chosen after the coherent evidence operation earned its own contract.

## Consequences

The descriptor registry, help, schema snapshots, published-binary tests, limits, authority metadata, and performance matrix cover all six operations. budget.insights.evidence.get is read-only, BUDGET-owned, bounded, and visible to compatible consumers; it grants no mutation or analytical authority.
