# Transactional replay from immutable outcome references

> Generated from the lex graph. Do not edit this file as source of truth; update graph entities and re-export.

**Status:** accepted
**Status Notes:** Accepted. Same-operation replay is the documented recovery path; no extra status operation is introduced.
**Ref Code:** DD-BUDGET-IDEMPOTENT-MUTATIONS

## Description

Make draft creation and activation safe across caller retry, process interruption, and result-delivery loss without duplicating financial payloads.

## Decision

Require a module-wide idempotency key for both mutations. Compare contract version, operation ID, key digest, and a canonical source-generated logical-request hash including actor, reason, selectors, and category-ID-sorted entries. Commit the mutation, lifecycle events, result hash, and stable outcome references in one local transaction. Mutation results contain the immutable payload and exact cited lifecycle-event snapshots but exclude live period state, later revision status, and current category enrichment. Rehydrate replay results from those immutable rows; do not persist a serialized financial response copy.

## Rationale

A uniqueness check alone cannot resolve commit-before-delivery. Storing full response JSON duplicates sensitive plan amounts and couples durability to a wire version. Immutable revision and lifecycle rows already contain the exact logical result, so stable references close the interruption window with less sensitive duplication.

## Alternatives

A: caller retry without records, rejected as duplicate-prone. B: store full request/response JSON, rejected for privacy and schema duplication. C: transactional fingerprints plus immutable outcome references, chosen.

## Consequences

Exact same replay returns the original plan/revision IDs, statuses, actor, reason, and timestamps even after period closure or later category change. A different operation or logical input with the same key conflicts. Boundary validation and transient pre-transaction failures do not consume the key. Fault injection must cover every commit and delivery cut point.
