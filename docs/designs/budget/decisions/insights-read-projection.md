# Reuse exact owner reads through a mutation-free INSIGHTS capability set

**Ref Code:** DD-BUDGET-INSIGHTS-READ-PROJECTION

## Description

Give INSIGHTS stable raw plan, exact position, and dated actual evidence without granting plan mutation, copying projection logic, or permitting mixed corrected states.

## Decision

Publish BudgetPlanRevisionDetail and BudgetPosition as the shared owner and INSIGHTS read DTOs. Publish a versioned BudgetReadCapabilityDescriptor containing budget.plan.revision.get, budget.position.get, and the read-only budget.insights.evidence.get operation. The composite first resolves planState as BoundRevision, NoBudgetPlan, or NoActiveBudgetPlanRevision. It invokes the released LEDGER actuals query once for every valid period state and returns bounded dated ActualsItem members, exact ledgerBudgetActualTotal, shared snapshot provenance, and one evidence-binding fingerprint. BoundRevision also returns immutable plan detail and the canonical BudgetPosition calculated from that same complete member set. The two plan-absence states return no plan detail or BudgetPosition and never invoke the calculator. A future concrete INSIGHTS client invokes only these released descriptors through the shared operation executor. No mutation descriptor, private storage, second LEDGER read, duplicated calculator, transport port, report state, analytics field, or consumer state crosses this boundary.

## Rationale

A second INSIGHTS projection or calculation would drift from what the owner reconciles, while exposing every BUDGET descriptor would make mutation authority ambiguous. The 2026-07-20 A3 spike proved that independent position and actuals reads mix corrected generations and that one BUDGET-owned snapshot can supply a coherent bound-plan result. The INSIGHTS PRD also requires exact actual metrics when plan intent is absent, so the same composite must preserve explicit NoBudgetPlan and NoActiveBudgetPlanRevision states while returning only the public snapshot members and total. This avoids fabricating an empty plan or forcing INSIGHTS to query LEDGER.

## Alternatives

A: duplicate INSIGHTS DTOs and calculation, rejected for parity drift. B: keep independent budget.position.get and ledger.actuals.query calls, rejected by the A3 correction-race control. C: expose a consumed LEDGER cursor to INSIGHTS, rejected for expiry and cross-owner cursor coupling. D: keep exact owner reads and add one BUDGET-owned composite evidence read over the same materialized snapshot, chosen.

## Consequences

Consumer compatibility tests prove all three plan states, schema identity, provenance completeness, bound-plan member and position reconciliation, plan-absence member and ledger-total reconciliation, forced concurrent-correction behavior, resource bounds, forbidden analytics fields, and absence of mutation operations. Existing plan and position reads remain unchanged. Only BoundRevision invokes BudgetPositionCalculator. INSIGHTS owns reports and interpretation and treats LEDGER as cited transitive provenance. The dependency remains assumed until production conformance validates the pairing.
