# Consume category and actuals truth only through released LEDGER operations

**Ref Code:** DD-BUDGET-LEDGER-PUBLIC-COMPOSITION

## Description

Validate categories and obtain complete corrected Budget Actuals without private storage access or duplicated finance semantics.

## Decision

Use the concrete shared LedgerContractClient to resolve and invoke released ledger.category.list/get and ledger.actuals.query descriptors through the public operation executor. Draft and activation cite the compatible category contract and require every referenced stable category to be active in the returned lifecycle evidence. Position maps the Budget Period [startInclusive,endExclusive) to LEDGER's inclusive filters as effectiveDateFrom=startInclusive and effectiveDateTo=endExclusive.AddDays(-1), uses active transaction/current allocation state, transfer principal excluded, refunds netted, and categorized plus uncategorized membership. Every page must share one snapshot and all ordinals must be complete. Any non-null assigned category is bucketed by plan membership even when its current lifecycle is archived; unknown category evidence is an integrity failure.

## Rationale

LEDGER owns category identity, allocation, transfer, refund, correction, void, supersession, and snapshot semantics. Direct SQL, handlers, or private types would make compatibility tests false. Recomputing actuals in BUDGET would create two finance engines. The existing public client and executor are already a real cross-module seam; an additional port would be speculative.

## Alternatives

A: direct LedgerDb/SQL, rejected as forbidden. B: direct feature handlers, rejected because it bypasses released schemas. C: spawn the CLI child process, rejected as needless process and cancellation complexity. D: invoke released descriptors in-process through the shared concrete client, chosen.

## Consequences

An incompatible category or actuals contract fails before BUDGET mutation or financial output. A failed, expired, incomplete, duplicate, or mixed snapshot yields no partial position. BUDGET never invokes a LEDGER mutation. Published-binary and in-process conformance remain an upstream implementation gate.
