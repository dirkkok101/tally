## Description

Make every first-release classification capability, mutation boundary, error, limit, and replay rule discoverable without HTTP or hidden action discriminators.

## Decision

Expose exactly classify.evaluate, classify.outcome.get, classify.apply.preview, classify.apply.run, classify.rule.save, classify.rule.validate, classify.rule.activate, classify.rule.retire, classify.feedback.record, classify.status, classify.abandon, and classify.cleanup. One explicitly registered descriptor registry generates CLI dispatch, help, schema, compatibility, stable errors, limits, mutability, idempotency metadata, and process envelopes. Complex input uses explicit stdin or file JSON and every invocation emits one business envelope.

## Rationale

A generic invoke, manage, run, save, or delete surface would move operation knowledge into callers and weaken schema discovery. A three-entry facade is smaller only syntactically. Separate help, schema, and dispatch definitions would drift. The selected shape reuses the established Ledger and Ingest public process contract while honoring the canonical PRD vocabulary. HTTP Save, GetGridList, GetLookupList, and Delete endpoints are inapplicable because CLASSIFY is a channel-neutral local CLI module.
