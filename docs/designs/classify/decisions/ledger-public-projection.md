# Use purpose-scoped classification projections on the public Ledger actuals contract

> Generated from the lex graph. Do not edit this file as source of truth; update graph entities and re-export.

**Status:** accepted
**Ref Code:** DD-CLASSIFY-LEDGER-PUBLIC-PROJECTION

## Description

Acquire complete eligible evaluation inputs and exact current apply-preflight state, including already-categorized corrections, without private Ledger reads or duplicated relationship semantics.

## Decision

Extend the next compatible ledger.actuals.query contract with a closed purpose of evaluation or apply_preflight and itemProjection classification_v1. Evaluation fixes categorizationState to requires_independent_decision. Apply preflight requires a bounded transactionIds selection and returns every selected transaction with Ledger-owned assignable, correctable, or ineligible mutation state plus current allocation identity and revisions, including already-categorized transactions. The first page returns snapshot and projection versions, store generation, expiry, category identity lifecycle fingerprint, active category catalogue, and ordered minimal classification items. Assignment asserts no active allocation; correction carries the expected active allocation identity and projection revisions so Ledger can reject drift atomically. Invoke projection and mutation operations through the concrete shared LedgerContractClient and released operation executor only.

## Rationale

One public projection family preserves stable ordering and Ledger-owned categorization, transfer, refund, relationship, allocation, and lifecycle truth, but evaluation eligibility and apply preflight have different membership. A single requires-independent-decision filter cannot preflight explicit corrections because those transactions are already categorized. Purpose-scoped requests make that distinction closed and discoverable. Current allocation and revision preconditions close the race between preview, all-item preflight, and each Ledger write. Direct SQL or handlers violate the boundary; re-inferring eligibility in CLASSIFY duplicates finance semantics; a private query cannot be compatibility-tested. The extension remains a hard upstream gate until published-binary conformance passes.
