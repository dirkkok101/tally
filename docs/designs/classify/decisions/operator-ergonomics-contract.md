## Decision

Expand the existing CLASSIFY module with classify.outcome.list, classify.rule.list, classify.rule-set.active.get, classify.corpus.build, and classify.unresolved.report under contract version 1.0. CLASSIFY remains the sole owner of outcome and rule discovery, active rule-set state, selected-outcome preview composition, private corpus construction, and unresolved reporting; no operator-ergonomics module or duplicate product boundary is permitted. Keep all twelve 0.3.3 request, result, and error schemas compatible. Do not extend classify.status or classify.apply.preview: outcome.list composes with the existing selected_outcomes preview mode and its 200-outcome maximum. The resulting published inventory is 105 total operations and 17 CLASSIFY operations. All five operations compose through the existing typed envelope, source-generated JSON, shared operation registry, CLASSIFY handler module, exit-code mapping, idempotency conventions, and metadata-only diagnostics. The shipped Ledger classification_v1 projection is consumed read-only. Any genuinely new projection, query, lifecycle, or mutation-precondition contract must be specified and implemented under the existing LEDGER module before CLASSIFY consumes it.

## Rationale

The shipped core classifier is already a coherent CLASSIFY boundary; operator throughput and discoverability are additive capabilities of that product, not a new domain. Separate operations keep mutability, limits, privacy, and lifecycle semantics inspectable. A status extension would alter a strict released result shape, and a preview extension is unnecessary because explicit outcome IDs already provide the required batch contract. Preserving LEDGER ownership prevents CLASSIFY from reconstructing financial truth, while reusing the existing process, registry, schema, and handler-composition artifacts avoids a parallel platform boundary.

## Alternatives

Change classify.status; rejected to preserve its released schema. Add apply-all or preview-by-filter; rejected because it weakens explicit selection and broadApplyAllowed=false. Use one generic discovery operation; rejected because rule, outcome, corpus, and unresolved-report authority differ.

CLASSIFY tasks may modify shared registry composition only to register their CLASSIFY descriptors and handlers under the established process/schema contracts. They may not change Ledger projection semantics; a discovered Ledger contract gap stops the affected task and requires an audited LEDGER entity, dependency, and verification path. Rollback removes only the five new descriptors and handlers before release or restores the prior binary after release; durable engine state remains readable by 0.3.3, while a corpus file written by the new builder remains an ordinary private validation corpus.
