# Use fingerprint-bound keyset cursors for outcome and rule discovery

> Generated from the lex graph. Do not edit this file as source of truth; update graph entities and re-export.

**Status:** accepted
**Ref Code:** DD-CLASSIFY-PAGINATED-DISCOVERY

## Description

Defines deterministic bounded pagination, filters, snapshot semantics, cursor failures, and no-partial-result behavior.

## Decision

Both list requests require pageSize from 1 through 500 and accept one opaque versioned base64url continuation whose canonical payload carries a SHA-256 checksum and is never mutation authority. Outcome pages require evaluationId, order by ordinal then transactionId, and bind the cursor to operation ID, evaluation ID, normalized filters, page size, evaluation/result fingerprint, rule-set fingerprint, category lifecycle fingerprint, Ledger generation, expiry, and last key. Rule pages order by createdAt then ruleVersionId and bind the first-page high-water key, filters, page size, authority/category fingerprints, expiry, and last key so later appends do not enter an existing traversal. Every supplied filter is ANDed. Cursor decoding, checksum validation, and compatibility validation complete before any page result is constructed. Invalid, expired, cross-request, incompatible, or stale cursors return typed errors with null result and exit class 7; integrity failures return the existing integrity exit class. No partial page is returned.

## Rationale

Keyset pagination is deterministic and bounded without OFFSET drift. Fingerprint binding prevents a cursor from authorizing a different evaluation, filter, category lifecycle, rule set, or Ledger generation.

## Alternatives

Offset pagination; rejected because concurrent immutable appends and retention changes can duplicate or omit rows. Server-side cursor state; rejected because it adds cleanup state. Caller-provided continuation fields; rejected because they become an accidental public contract and cannot bind the complete request/snapshot fingerprint.

## Consequences

A shared code-owned cursor codec and closed error vocabulary are required. Outcome listing refreshes compatible Ledger/category lifecycle evidence before exposing transaction/category display data. Rule listing freezes an immutable high-water boundary. Tests cover exact limit, one over, expiry, filter mismatch, generation drift, archived category, missing authority, tampering, and deterministic replay.
