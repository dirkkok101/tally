## Description

Defines the local corpus builder boundary, exact-label mapping, idempotency, filesystem protection, recovery, and disclosure rules.

## Decision

classify.corpus.build accepts an idempotency key, a fresh complete Ledger classification_v1 evaluation projection, explicit owner labels of transactionId plus expected outcome/category, and an explicit absolute output path. It never derives or invents a label. A shared ClassificationProjectionCorpusMapper maps each label to exactly one projection row and emits the existing JSONL corpus schema and lifecycle fingerprints. The builder requires a contained owner-owned 0700 directory and a non-symlink regular-file destination, rejects hard-link or owner/mode ambiguity, enforces closed row and byte limits before publication, creates a recognized same-directory 0600 temporary file before writing bytes, writes and flushes the complete file, validates it through PrivateCorpusReader, atomically renames only when the destination does not contain different content, flushes parent-directory metadata after the rename, and only then records terminal success. It never overwrites a different existing file. Replay after an interrupted response may accept an existing destination only when its full fingerprint equals the terminal idempotency receipt; request and result metadata never persist or return the output path.

## Rationale

The validation boundary already trusts only owner-private JSONL. Reusing its mapper and reader prevents a second corpus dialect. Same-directory atomic rename prevents partial publication, and flushing parent-directory metadata after rename establishes the durable directory entry before terminal success.

## Alternatives

Infer labels from current categories; rejected because labels must be explicit. Stream rows to stdout; rejected because descriptions would enter orchestration logs. Persist the output path for recovery; rejected because private paths are prohibited. Write directly to destination; rejected because interruption could publish a partial corpus.

## Consequences

The command is the only new query-like operation that mutates a caller-selected private file, never Ledger or CLASSIFY financial state. It reuses the existing operation_idempotency request fingerprint and terminal_result columns, stores no path or row, and requires no schema migration. Failures remove only the recognized temporary or leave it for fixed startup/next-run recovery; they never unlink an existing destination. Results contain counts, fingerprints, lifecycle IDs, and terminal state only.
