# Memory-only private corpus validation with aggregate durability

> Generated from the lex graph. Do not edit this file as source of truth; update graph entities and re-export.

**Status:** accepted
**Ref Code:** DD-CLASSIFY-PRIVATE-VALIDATION

## Description

Gate rule and normalization activation on representative owner evidence without retaining or disclosing raw financial rows.

## Decision

Read one bounded owner-only JSONL corpus path only from private structured input, open read-only without following the final symbolic link, fingerprint exact bytes, and stream rows through the production normalization and evaluation engine. Persist only candidate, corpus, expected-outcome, projection, category, normalization, and rule-origin fingerprints plus aggregate counts and canary outcomes. For owner-authored rulebooks require every row accounted for, zero incorrect applications, zero unexplained incompatible conflicts, explicit coverage and no-suggestion totals, deterministic fingerprints, and drift canaries before activation or broad authority. Measure owner decisions and time benefit separately; do not impose the failed automatic-discovery 50 percent threshold on this track, and require an explicit product decision if benefit is insufficient.

## Rationale

Copying corpus data into the state store or graph increases disclosure and retention. An external validation service violates locality. A separate evaluator risks semantic drift. Aggregate-only durability satisfies activation proof while the production engine makes validation representative. The owner-authored track has mandatory safety gates but a distinct value hypothesis from automatic discovery. If the corpus is unavailable, preserving the last active rule set while blocking new authority is the only fail-closed behavior consistent with the PRD.

## Alternatives

Rejected copying private corpus rows into classify.db or tracked reports because it expands disclosure and retention. Rejected external or cloud validation because financial evidence must remain owner-local. Rejected a separate validation evaluator because it can drift from production semantics. Rejected activating new rule authority when the corpus is unavailable because absence of evidence cannot establish a zero-incorrect-application gate.
