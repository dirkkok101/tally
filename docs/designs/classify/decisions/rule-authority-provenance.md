# Record minimal rule authority provenance

> Generated from the lex graph. Do not edit this file as source of truth; update graph entities and re-export.

**Status:** accepted
**Ref Code:** DD-CLASSIFY-RULE-AUTHORITY-PROVENANCE

## Description

Distinguish deliberate owner authorship from feedback-derived proposals without persisting private source material.

## Decision

Add a closed rule_origin value of owner_authored or feedback_derived to immutable rule versions and proposals. Keep created_by, reason, scope_hash, prior_version_id, and source feedback reference as the remaining provenance. rule.save is the only public entry for owner_authored drafts. feedback.record may create at most one feedback_derived non-active proposal. Neither origin grants validation, activation, broad apply, or mutation authority, and no personal rule value is compiled, seeded, logged, or exported.

## Rationale

created_by alone cannot distinguish an owner-authored rule deliberately entered through rule.save from a draft proposed after feedback when the same owner or Hermes process invokes both. One closed origin enum resolves that audit ambiguity without retaining a private note locator, transaction payload, or generalized training lineage.

## Alternatives

Rejected relying only on created_by because one actor can create both authority tracks. Rejected free-form provenance because it is not finite or testable. Rejected retaining source descriptions, normalized tokens, private paths, or model features because they expand disclosure. Rejected origin-based activation because provenance describes history rather than authority.

## Consequences

Every rule version and proposal carries one finite origin. Feedback-derived drafts must still use the normal save, validation, and explicit activation path; owner-authored drafts receive no implicit trust.
