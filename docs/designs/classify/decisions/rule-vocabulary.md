# Closed typed rule grammar with code-owned normalization versions

> Generated from the lex graph. Do not edit this file as source of truth; update graph entities and re-export.

**Status:** accepted
**Ref Code:** DD-CLASSIFY-RULE-VOCABULARY

## Description

Keep owner-managed rules deterministic, reviewable, Native-AOT safe, and incapable of executing arbitrary expressions.

## Decision

Represent every immutable rule version as one or more AND-combined typed conditions over classification_v1 fields. Allow description.normalized equals, starts_with, and contains_token_sequence; account.id equals; amount.direction equals; and amount.absolute_minor equals or between_inclusive. Normalization v1 performs Unicode NFKC, invariant case folding, punctuation boundaries, and whitespace collapse while preserving digits and token order. Forbid OR, NOT, priority, regex, fuzzy, wildcard, script, plugin, and model-score predicates.

## Rationale

A normalized typed grammar makes validation, canonical hashing, persistence, explanation, and property testing finite. Arbitrary JSON expressions have two readings and invite executor drift. Regex or plugins expand denial, injection, and AOT risk. Delegating interpretation to the Agent Host makes outcomes session-dependent. The exact small registry is subject to the private projection and normalization spike; failed evidence routes back to design or the do-less path rather than permitting silent grammar expansion.
