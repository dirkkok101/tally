# Separate raw-SQLite classification state with immutable history

> Generated from the lex graph. Do not edit this file as source of truth; update graph entities and re-export.

**Status:** accepted
**Ref Code:** DD-CLASSIFY-STATE-STORE

## Description

Persist rule lifecycle, outcomes, apply recovery, feedback, and cleanup without coupling their retention to Durable Ledger State.

## Decision

Use one owner-only classify.db under the Tally data root with Microsoft.Data.Sqlite, snake_case tables, foreign keys, WAL, synchronous FULL, bounded busy handling, user_version migrations, explicit transactions, operation idempotency, and guarded single-writer transitions. Immutable versions, outcomes, terminal item results, feedback, and lifecycle rows reject update and delete. Raw corpus rows and full Ledger projections are never persisted.

## Rationale

Sharing Ledger storage violates the public boundary and couples retention. Flat JSON files make atomic activation, row accounting, migrations, idempotency, and saga recovery fragile. A hosted database violates the self-contained constraint. EF and DbContext add a mapping and migration layer without a second provider or hosted request pipeline. Raw SQLite matches the established Tally storage model and permits exact invariant tests.
