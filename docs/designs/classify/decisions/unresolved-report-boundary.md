# Generate unresolved-pattern reports without durable descriptions

> Generated from the lex graph. Do not edit this file as source of truth; update graph entities and re-export.

**Status:** accepted
**Ref Code:** DD-CLASSIFY-UNRESOLVED-REPORT-BOUNDARY

## Description

Defines owner-local grouping, fresh Ledger join, privacy, drift detection, and non-authority semantics.

## Decision

classify.unresolved.report is a read-only bounded report over retained no_suggestion outcomes from one completed evaluation joined by transaction ID to a fresh compatible Ledger classification_v1 projection. It groups by normalizationVersion, normalizedDescription, accountId, and amountDirection; aggregates count and signed/absolute minor-unit totals with checked arithmetic; orders by count descending then normalizedDescription, accountId, and direction using ordinal comparison; and returns at most topN from 1 through 500. Each group exposes an owner-visible normalized description, direction/account scope, aggregate amounts, contributing count, evaluation/projection/category/rule-set fingerprints, and a group fingerprint. It creates no table, cache, artifact, rule, proposal, feedback, or activation and logs no description, token, amount, path, or transaction ID. Missing/expired evaluation, stale Ledger generation, incompatible projection, retention gaps, or row-accounting mismatch fail with typed errors and null result.

## Rationale

Owner review needs repeated unresolved patterns, but persisting another raw-description index would expand retention and disclosure risk. The public Ledger projection supplies the current owner-visible value at query time.

## Alternatives

Store normalized descriptions with outcomes; rejected as a new durable sensitive index. Group only by hash; rejected because the owner cannot review a candidate. Create draft rules automatically; rejected because a report carries no rule authority.

## Consequences

The report is ephemeral owner-local output and is not a corpus or authority receipt. Re-running against the same evaluation and compatible projection yields identical ordering and fingerprints. Drift requires a new invocation; no continuation survives an incompatible generation.
