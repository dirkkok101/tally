## FormatVariantAndSourceEvidence

**Ref Code:** DM-INGEST-FORMAT-EVIDENCE

In-memory passive document evidence and the real two-adapter seam.

### Schema

FormatVariantDescriptor {variantId, adapterVersion, extractionPolicyVersion, manifestSchemaVersion, supportedMediaType, hardLimits}
PdfGlyphEvidence {value, left, bottom, right, top, baselineY, textSequence, contentOrder}
PdfManagedLineEvidence {pageNumber, blockOrdinal, lineOrdinal, text, left, bottom, right, top}
PdfPageEvidence {pageNumber, width, height, orderedGlyphs[], managedLines[]}
PdfDocumentEvidence {sourceFingerprint, byteLength, ordered pages[]}
VariantProbeResult {variantId, outcome: no_match|exact_match|unsafe, structuralEvidenceCodes[]}
StatementAccountEvidence {accountId, accountClass, currencyCode, maskedIdentifier, metadataFingerprint, matched}
DescriptionEvidenceKind {source_text, source_absent_marker}
SourceRecordEvidence {sourceRecordId, pageNumber, recordOrdinal, recordKind, originalTextEvidence, sourceReference?, financialEvidence: FinancialEvidence, runningBalanceMinor?, sourceControlMinor?, descriptionEvidenceKind}
ExtractedStatement {variant, statementPeriod: StatementPeriod, accountEvidence, orderedRecords[], openingEconomicBalanceMinor?, closingEconomicBalanceMinor?, advertisedControls[]}

PdfManagedLineEvidence is deterministic, bounded, in-memory output from PdfPig NearestNeighbourWordExtractor plus DefaultPageSegmenter during the same passive extraction pass; no PDF objects, source bytes, or managed-line text are persisted or logged. FinancialEvidence and StatementPeriod reuse existing INGEST contracts. Adapters extract FinancialEvidence without AccountClass sign conversion; preview applies selected AccountDetail.AccountClass through FinancialNormalizer and then passes movements plus extracted controls to StatementReconciler. Layout A follows DD-INGEST-FORMAT-ADAPTERS and DD-INGEST-SOURCE-DESCRIPTION-ABSENCE. Layout B requires one Date, Details, Amount managed header per page; exactly two distinct full dates in content order; yearless row anchors at managed-line start; final signed money movement; a unique description glyph band grouped at 0.1 point baseline tolerance, bounded by header ratios 0.33 and 0.75, associated within 5 points of managed-line bottom, and contained in normalized row text; unique opening and closing controls; and exact reconciliation. originalTextEvidence contains only the managed row source text and matched description glyph source text. Layout B metadata fields are managed lines in source page, block, and line order containing account or card after monetary-token removal. metadataFingerprint is lowercase SHA-256 over adapterVersion, LF, then normalized fields joined by LF without trailing LF; fields use FormKC, invariant lowercase, and whitespace collapse. Paths, filenames, selected accountId, transaction rows, and financial values are excluded. Any structural ambiguity fails closed. IStatementAdapter exposes Descriptor, Probe(PdfDocumentEvidence), and Extract(PdfDocumentEvidence, exact released AccountDetail). V1 registers exactly two adapters and requires one exact probe match.

## LedgerCommitContractSnapshot

**Ref Code:** DM-INGEST-LEDGER-COMMIT-CONTRACT

Exact released LEDGER record input, deterministic statement evidence derivation, frozen envelope, immutable round-trip verification for reference-bearing accepted and Exact Duplicate outcomes, and durable reference-free terminal semantics for conflicted and rejected outcomes.

### Schema

FrozenLedgerRecordRequest {ledgerContractVersion, operationId: ledger.transaction.record, idempotencyKey: ingest:{candidateId}, actor, input: RecordTransactionInput{accountId, signedAmount canonical decimal string, currencyCode: ZAR, transactionDate, postingDate?, originalDescription, instrumentId: null in v1, cardholderId: null in v1, initialEvidence: RegisterEvidenceInput{kind: statement_row, logicalIdentityDigest: candidateId, opaqueExternalReference: ingest:{candidateId}, contentFingerprint: sourceRecordId, observation: EvidenceObservation{accountId, signedAmountMinor, currencyCode: ZAR, transactionDate, postingDate?, instrumentId: null, cardholderId: null, descriptionFingerprint: lowercase SHA-256 of UTF-8 normalized originalDescription}}}}
LedgerImmutableVerification {transactionId from record, accountId, signedAmount, currencyCode, transactionDate, postingDate?, originalDescription, instrumentId?, cardholderId?, exactly one initial evidence with kind, logicalIdentityDigest, opaqueExternalReference, contentFingerprint, and observation equal to the frozen input}

Preview constructs and persists this request once. originalDescription is the exact normalized source description when DescriptionEvidenceKind=source_text. When DescriptionEvidenceKind=source_absent_marker, it is the exact fixed value 'Description unavailable in source statement' governed by DD-INGEST-SOURCE-DESCRIPTION-ABSENCE; the marker is never presented as source glyph evidence. Candidate identity and descriptionFingerprint use that same final exact string. Commit and resume serialize the stored input byte-equivalently through the released LedgerJsonContext. ledger.transaction.get uses IncludeHistory=false. Terminal verification compares LedgerImmutableVerification only, including byte-exact originalDescription and InitialEvidence equality; History, lifecycle, category, pool, reconciliation, recorded actor, and recorded time are projections or metadata and are excluded. No private LEDGER type or store handle crosses the boundary.

## IngestStateStore

**Ref Code:** DM-INGEST-STATE-STORE

Separate owner-only raw-SQLite state with immutable V001 workflow tables, V002 durable error events, ephemeral stable status snapshots, recovery, compaction, and safe cleanup.

### Schema

V001 remains immutable: ingest_batch, manifest_revision, source_record_outcome, import_candidate, reconciliation_control, manifest_approval, import_receipt, candidate_receipt.
V002 adds ingest_store_metadata(singleton_id INTEGER PRIMARY KEY CHECK(singleton_id=1), generation_id TEXT NOT NULL UNIQUE); batch_error_event(error_event_id TEXT PRIMARY KEY, batch_id TEXT NOT NULL REFERENCES ingest_batch ON DELETE RESTRICT ON UPDATE RESTRICT, sequence INTEGER NOT NULL, code TEXT NOT NULL, category INTEGER NOT NULL, safe_message TEXT NOT NULL, candidate_id TEXT, mutation_possibility INTEGER NOT NULL, durable_state TEXT, retry_action INTEGER NOT NULL, field TEXT, recorded_at TEXT NOT NULL, UNIQUE(batch_id, sequence)); status_snapshot(snapshot_id TEXT PRIMARY KEY, contract_version TEXT NOT NULL, store_generation TEXT NOT NULL, created_at TEXT NOT NULL, expires_at TEXT NOT NULL, total_count INTEGER NOT NULL); status_snapshot_item(snapshot_id TEXT NOT NULL REFERENCES status_snapshot ON DELETE CASCADE ON UPDATE RESTRICT, ordinal INTEGER NOT NULL, batch_status_summary_json TEXT NOT NULL, PRIMARY KEY(snapshot_id, ordinal)). batch_error_event rows reject update/delete except explicit terminal batch cleanup under the cleanup transaction. status_snapshot rows are explicitly ephemeral, metadata-only, excluded from completed receipts and backup authority, immutable after insert, and cascade-delete on expiry or store cleanup.

The migration runner applies V001 then V002 in order and sets user_version=2 in the same protected migration sequence; V001 is never edited. Foreign keys are ON, WAL and synchronous FULL are required, and owner-only permissions apply to database, WAL, and SHM.

V003 adds import_receipt.created_at TEXT and import_receipt.updated_at TEXT: durable receipt provenance set once at insert and updated only on real state transitions; migration backfills existing rows from the owning ingest_batch timestamps (completed_at preferred for updated_at), never a fabricated epoch. V004 adds candidate_receipt.attempt_count INTEGER NOT NULL DEFAULT 0: a monotonic durable attempt counter (0 = never attempted) incremented on every MarkAttempting upsert; migration backfills 1 where attempted_at IS NOT NULL. The migration runner applies V001 through V004 in order and sets user_version=4 in the same protected migration sequence.
