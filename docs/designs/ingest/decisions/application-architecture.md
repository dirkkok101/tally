# Single-process vertical slices with isolated ingestion state

## Description

Place INGEST in the existing Native-AOT Tally executable while preserving its public boundary and private state ownership.

## Decision

Use one executable with vertical slices for Contract, Preview, Review, Commit, and Recovery; pure Domain/Ingest policies; concrete PdfPig and raw-SQLite infrastructure; explicit DI; and no HTTP, daemon, mediator, event bus, generic repository, or plugin loader. INGEST owns a separate state store and reaches LEDGER only through the shared public operation executor.

## Rationale

This adopts ADR-CORE-0021 and ADR-CORE-0024 plus the deep-module shape of MD-LEDGER-MASTER while respecting C1 and C2. A separate service adds deployment and authentication complexity; direct integration into LEDGER features erases the module boundary; horizontal technical layers scatter one ingestion workflow across the solution.

## Alternatives

A: separate INGEST service with HTTP or RPC, rejected because it adds hosting, auth, deployment, and network failure modes. B: embed parsing in LEDGER, rejected because it contaminates the canonical finance core and reverses dependency direction. C: one executable with isolated vertical slices and state, chosen.

## Consequences

INGEST ships and versions with Tally, shares system operation infrastructure, and remains independently testable through its public contract. Module isolation is enforced by project paths, dependency tests, separate storage, and public-operation-only LEDGER access rather than a process boundary.
