# Managed in-process PDF extraction with PdfPig

> Generated from the lex graph. Do not edit this file as source of truth; update graph entities and re-export.

**Status:** accepted
**Status Notes:** Accepted from OQ-INGEST-11 spike. The production paths do not exist yet and are mandatory plan targets.
**Ref Code:** DD-INGEST-DOCUMENT-EXTRACTION

## Description

Choose the passive PDF text and glyph-position extraction dependency for the two qualified INGEST Format Variants inside the self-contained Native-AOT Tally CLI.

## Decision

Pin the upstream PdfPig package at version 0.1.14 for the first qualified adapter set. A concrete PdfStatementTextExtractor reads caller-owned bytes inside the Tally process and returns ordered page, glyph, text, and coordinate evidence to the two format-specific adapters. It never executes active content, follows external links, renders pages, performs OCR, or mutates the source. Unsupported encryption, scans, malformed structures, ambiguous layouts, changed layouts, and configured resource bounds fail closed. Package version and extraction-policy version are included in the adapter compatibility identity. Do not introduce a generic PDF parser port until a second real implementation exists.

## Rationale

Spike OQ-INGEST-11 on 2026-07-18 published a trimmed self-contained linux-x64 .NET 10 Native-AOT harness against the current upstream PdfPig 0.1.14 package. All three qualified fixtures, including the permission-encrypted fixture, produced non-empty page/glyph evidence twice with identical digests. Worst observed invocation was 0.37 seconds and 51,416 KiB peak RSS versus the 5-second and 256-MiB limits. The legacy UglyToad.PdfPig 1.7.0-custom-5 package published with trim warnings and failed at runtime because its reflection factory was trimmed. Poppler child-process extraction was rejected because it adds distribution, process-lifecycle, and source-path handling complexity; a custom PDF parser was rejected as unsafe and out of scope.

## Alternatives

A: legacy UglyToad.PdfPig 1.7.0-custom-5, rejected after a trimmed Native-AOT runtime failure. B: Poppler child process, rejected for distribution, process, cancellation, and source-path complexity. C: custom PDF parsing, rejected as unsafe and outside scope. D: upstream PdfPig 0.1.14 in-process, chosen by published-binary fixture evidence.

## Consequences

PdfPig is pinned; every upgrade reruns Native-AOT publish, deterministic private golden fixtures, malformed-input bounds, and permission-encrypted coverage before an adapter version can change. PdfPig types remain inside Infrastructure/Ingest/Pdf.
