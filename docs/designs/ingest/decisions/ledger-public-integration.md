## Description

Preserve the discoverable cross-module contract without a child process or private handler coupling.

## Decision

Use one concrete LedgerContractClient that resolves released LEDGER operation descriptors and invokes the shared typed operation executor. Preview freezes the exact released RecordTransactionInput shape. InitialEvidence is EvidenceKind.statement_row; LogicalIdentityDigest is the stable lowercase 64-hex candidateId; OpaqueExternalReference is the existing ingest:{candidateId} sourceReference; ContentFingerprint is the stable lowercase 64-hex sourceRecordId; Observation repeats accountId, signedAmountMinor, currencyCode, transactionDate, postingDate, null v1 instrument/cardholder IDs, and a lowercase SHA-256 over the UTF-8 normalized OriginalDescription. Actor, contract version, operation ID, and the ingest:{candidateId} idempotency key remain in the frozen request envelope. Commit passes that byte-equivalent frozen input without client-side reshaping. For accepted and Exact Duplicate outcomes that carry a canonical transaction reference, ledger.transaction.get uses IncludeHistory=false and terminal verification compares transactionId plus only the frozen immutable financial, attribution, and InitialEvidence facts. It requires exactly one matching initial evidence record and ignores History, lifecycle/category/pool/reconciliation projections, recorded actor, and recorded time. A structured conflicted or rejected outcome is terminal only after its complete outcome is durably recorded with no canonical reference required; an unresolved outcome is non-terminal. INGEST never references LedgerDb, SQL, storage paths, feature handlers, or private domain types.

## Rationale

The passing 12-case LedgerIngestPrerequisiteTests contract proves the released input and evidence result shapes. CandidateId already carries the versioned account, source-row, and immutable-fact identity; sourceRecordId carries the versioned source, structural-position, raw-evidence, and immutable-facts identity. Freezing those values during preview preserves the approved request and closes the commit/resume crash window. Comparing mutable projections or optional History would turn a healthy canonical write into a false failure.

## Alternatives

A: retain sourceReference and provenance fields that LEDGER does not publish, rejected because the request cannot cross the public contract. B: translate an INGEST-only request into InitialEvidence inside LedgerContractClient, rejected because commit/resume would not replay the persisted public request byte-equivalently. C: freeze the exact public RecordTransactionInput with derived statement evidence during preview, chosen. D: compare the complete TransactionDetail including History and mutable projections, rejected because record and get legitimately differ and later projections can change.

## Consequences

FrozenLedgerRecordRequest and its tests must use the released InitialEvidence and Observation shape. Preview identity code owns all evidence derivation. Commit and resume send the stored public input unchanged. Reference-bearing accepted and Exact Duplicate outcomes round-trip through the immutable verification tuple and matching evidence only; they must not normalize an incompatible request or require History. Conflicted and rejected outcomes prove terminality through their complete durable structured result without fabricating or requiring a canonical reference.
