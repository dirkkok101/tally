**Ref Code:** DD-INGEST-SOURCE-DESCRIPTION-ABSENCE

## Description

The fixed owner-supplied Layout A format contains structurally complete transaction rows whose description field has no source glyph evidence. INGEST must accept those real statements without treating source absence as ambiguous financial evidence.

## Decision

For pdf-text-layout-a-v1, after exact date, transaction-amount, running-balance, and row-band ownership are established, zero description-only candidates means source description absence. The adapter emits DescriptionEvidenceKind.SourceAbsentMarker and sets FinancialEvidence.Description to the exact ASCII marker 'Description unavailable in source statement'. OriginalTextEvidence contains only source glyph text and never the marker. Exactly one owned description candidate uses the whitespace-normalized source text; more than one candidate remains ambiguous and blocks. Preview identity and mapping code consumes that final exact description, then derives candidate identity, the InitialEvidence description fingerprint, the frozen Ledger RecordTransactionInput.OriginalDescription, and byte-exact Ledger get verification. The adapter does not construct or own the Ledger request.

## Rationale

The supplied PDFs are the production input contract and no alternate export exists. Ledger requires a non-empty control-free OriginalDescription and round-trips it exactly. A fixed marker states the source limitation truthfully while preserving deterministic identity and review visibility; it does not invent merchant or financial content. Spike result: on 2026-07-26 with PdfPig 0.1.14, the owner-authorized ignored fixture produced deterministic transaction anchors and controls while some otherwise complete Layout A rows exposed zero description glyph candidates; the current adapter therefore no-matched without producing a statement or Ledger mutation.

## Alternatives

A: require a re-export, rejected because the fixed bank format is the only supplied format. B: accept owner-authored out-of-band descriptions, rejected because it introduces unproven financial provenance. C: send blank or null, rejected because the released Ledger contract rejects it and the absence would be invisible. D: borrow nearby text or use OCR, rejected because neither has deterministic row ownership. E: remove Layout A, rejected because it would exclude a required production statement.

## Consequences

SourceRecordEvidence gains a closed description-evidence kind. Layout A synthetic and private-fixture tests must prove exact marker emission only for zero-candidate rows, source text for unique candidates, rejection for multiple candidates, unchanged source evidence, deterministic normalization, and reconciliation. Preview and Ledger contract tests must prove that PreviewManifestMapper alone propagates the final exact description into candidate identity, InitialEvidence, the frozen public request, and immutable get verification. This is a pre-release correction inside adapter version 1.0.0; no released identity is migrated.
