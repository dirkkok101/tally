## Description

Choose the INSIGHTS module boundary, class organization, and interface economy inside the existing local Tally executable.

## Decision

Use eleven typed caller-oriented INSIGHTS operations plus shared schema discovery. Map each operation to one vertical slice around a deep InsightReportCompiler and concrete pure analytical policies, raw-SQLite storage, source-generated contracts, explicit DI, TimeProvider, a concrete BudgetContractClient over the shared public executor, and pure concrete mappers. Keep only the existing generic command and query handler abstractions; add no repository, store, compiler, calculator, clock, mapper, mediator, event, or transport interface.

## Rationale

The public operation set is the complete test surface and hides coherence, time, arithmetic, state accounting, provenance, replay, immutable history, deletion, and recovery. Removing INSIGHTS would smear those rules across Agent Host and CHANNELS. The shared operation executor is a real seam with multiple consumers; all proposed new ports would have one production implementation.

## Alternatives

A: a three-entry contract/report/storage facade, rejected because action discriminators expose every invariant to callers. B: eleven explicit operations plus shared discovery, chosen for contract and error clarity. C: full ports and adapters, rejected except for the already shared public executor because every new adapter would have one implementation.

InsightsContractMapper and InsightsRowMapper are concrete pure transformers. CancellationToken crosses every async boundary. No FastEndpoints, HTTP, EF, daemon, or background process is introduced.
