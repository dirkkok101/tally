## Description

## Decision

Expose insights.report.generate, insights.report.explain, insights.report.get, insights.report.list, insights.report.retain, insights.report.restate, insights.report.delete, insights.status.get, insights.backup.create, insights.backup.verify, and insights.restore.activate. Reuse system.schema.list and system.schema.show for Discover, including released policy catalogue metadata. One descriptor registry generates schemas, compatibility, limits, authority, mutability, idempotency, stable errors, exit categories, CLI help, and process envelopes.

## Rationale

One typed operation per accepted verb keeps invariants and failure modes visible and independently testable. Shared discovery avoids a duplicate INSIGHTS metadata command. Explicit process contracts preserve one automation surface for Agent Host and future CHANNELS without coupling analytical semantics to HTTP or UI.

## Alternatives

A: generic insights.execute with an action discriminator, rejected because it hides per-operation schemas, authority, and retry rules. B: HTTP or FastEndpoints routes, rejected because Tally is a local structured CLI with no listener. C: explicit operations from the shared registry, chosen.

## Consequences

Complex input uses stdin or owner-only file input; financial values and paths never use process arguments. Exactly one business envelope reaches stdout. Retain, Restate, Delete, Backup, and Restore require actor attribution and idempotency. Explain accepts one retained identity because ephemeral Generate already embeds explanations. No Save, Edit, Refresh, Alert, Notify, policy CRUD, or arbitrary Execute alias exists.
