## Description

Bind every Insight Report to one BUDGET-owned public producer result whose explicit planState, optional canonical Budget Position, dated actual members, and exact public LEDGER total represent one immutable source snapshot.

## Decision

INSIGHTS report generation consumes one versioned read-only budget.insights.evidence.get operation. BUDGET resolves BoundRevision, NoBudgetPlan, or NoActiveBudgetPlanRevision and captures one complete public LEDGER actuals snapshot for every valid state. BoundRevision returns one immutable Budget Plan Revision and the canonical BudgetPosition calculated from that same materialized set. Plan-absence states return no plan detail, BudgetPosition, or calculation schema, do not invoke the calculator, and return the same bounded dated ActualsItem shape plus exact ledgerBudgetActualTotal. Every result carries shared snapshot identity, generation fingerprint, contract versions, and evidence-binding fingerprint. INSIGHTS issues no second ledger.actuals.query and never calculates Budget Position. A correction before capture yields a wholly post-correction result; a correction after capture yields a wholly pre-correction result. Failure to prove one binding returns Source State Changed and no evidence result.

## Rationale

The 2026-07-20 disposable .NET 10 A3 harness proved the bound-plan protocol: 1000 of 1000 forced independent budget-position then ledger-actuals reads mixed generations, while one BUDGET-owned snapshot produced 1000 coherent pre-correction and 1000 coherent post-correction results with zero mixed or reconciliation failures. The approved INSIGHTS PRD additionally requires exact actual metrics when plan intent is absent. Preserving NoBudgetPlan and NoActiveBudgetPlanRevision inside the same composite is the only public shape that satisfies that requirement without fabricating a zero plan or forcing an independent LEDGER read. Production conformance must verify both the spiked bound path and the designed absence paths.

## Alternatives

A: keep independent budget.position.get and ledger.actuals.query calls, rejected because a correction between calls produced mixed evidence in every forced control. B: expose an opaque LEDGER cursor from BUDGET for INSIGHTS to resume, rejected because it adds expiry and cross-owner cursor coupling after BUDGET already materialized the complete snapshot. C: return the already materialized dated members with the canonical position in one BUDGET-owned read, chosen as the smallest coherent seam.

## Consequences

BUDGET publishes one bounded read-only discriminated result. BoundRevision proves member-to-position reconciliation and one calculator path; plan-absence states prove member-to-ledger-total reconciliation and calculator exclusion. BUDGET contract, design, plan, and conformance tests carry all three states, correction races, and resource bounds. INSIGHTS treats LEDGER as cited transitive provenance and owns all interpretation and retained state. No upstream mutation, cursor handoff, or analytical replica is introduced.
