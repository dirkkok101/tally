# Owner-only SQLite generations with canonical report payloads

> Generated from the lex graph. Do not edit this file as source of truth; update graph entities and re-export.

**Status:** accepted
**Status Notes:** Accepted. The logical store is INSIGHTS-owned and never read by another module.
**Ref Code:** DD-INSIGHTS-STATE-STORE

## Description

Persist immutable report evidence, metadata-first history, replay outcomes, and integrity state without creating an analytical replica.

## Decision

Use one logical INSIGHTS raw-SQLite store under generation directories selected by an owner-only CURRENT pointer. Persist normalized snapshot, Restatement, deletion, idempotency, and recovery metadata plus one canonical versioned JSON payload per retained snapshot. Released policy fingerprints used by a report remain inside that immutable report and store metadata needed for compatibility; private PolicyValidationReceipt evidence remains outside the active store. Use foreign keys, WAL, synchronous FULL, bounded busy handling, PRAGMA user_version, immutable migrations, BEGIN IMMEDIATE writers, and 0700 or 0600 protections. Never persist dated actual members, raw merchant text, producer cursors, canonical transactions, private corpus rows, arbitrary formulas, or private validation receipts.

## Rationale

JSON files make atomic multi-row retention, replay, RESTRICT deletion, and status integrity fragile. Fully normalized report bodies make immutable exact replay and schema evolution needlessly broad. EF or a hosted database adds layers with no second provider. A hybrid normalized envelope plus canonical payload supports bounded metadata reads, exact Get, content verification, and atomic mutation.

## Alternatives

A: store reports in BUDGET or LEDGER, rejected as authority coupling. B: loose canonical JSON files, rejected for transactional history and replay. C: fully normalized analytical rows, rejected because INSIGHTS must not become a duplicated time-series store. D: normalized metadata plus one canonical immutable report payload in raw SQLite generations, chosen.

## Consequences

List and Status use metadata columns without report payload reads. Get and Explain verify schema and content fingerprints. Real temporary SQLite is required in tests; SQL is not mocked. Host-managed encrypted-volume evidence remains a release gate and no custom encryption is claimed.
