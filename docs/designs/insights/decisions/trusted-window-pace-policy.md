# Frozen Johannesburg Analysis Windows and exact Linear Pace

## Description

Make time membership and the active plan-relative signal reproducible without caller clocks, locale drift, floating point, or forecast language.

## Decision

Freeze TimeProvider.GetUtcNow before producer reads. Convert with Africa/Johannesburg, derive inclusive day, Monday-week, and month-to-date windows clipped to the monthly Budget Period, use full historical periods, return Not Started for future periods, and reject rolling windows. Use LEDGER Effective Date for membership. Compute Linear Pace as exact rational plannedMinorUnits multiplied by elapsedDays divided by periodDays with checked arithmetic, full-plan overage precedence, and division-free zero-plan states.

## Rationale

Caller-supplied historical clocks would let a request mislabel current corrected producer evidence. Host locale would make week boundaries unstable. Decimal rounding or floating point would create irreproducible boundary states. The fixed calendar and exact rational policy matches the validated A6 owner workflow and remains explicitly a baseline rather than a Forecast.

## Alternatives

A: caller-supplied As-of Instant, rejected because it can imply unavailable historical source state. B: rolling windows and locale week starts, rejected as unsupported and ambiguous for v1. C: frozen trusted instant plus fixed Johannesburg calendar windows and exact rational pace, chosen.

## Consequences

Current-day incompleteness and uniform-distribution limitations are always emitted. No daily or weekly sub-budget is inferred. Int64 overflow, undefined exact operations, or reconciliation failure aborts the report. Historical generation states that current corrected evidence was used.
