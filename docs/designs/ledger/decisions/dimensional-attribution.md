# Independent local payment, category, and Spend Pool dimensions

**Status:** accepted

**Ref Code:** DD-LEDGER-DIMENSIONAL-ATTRIBUTION

## Description

Define stable provider-neutral attribution and pool semantics without conflating account, Payment Instrument, cardholder, category, or funding pool.

## Decision

Use local ULIDs and owner labels for instruments, cardholders, categories, and pools; allow optional masked suffixes but no full provider identifiers. Store instrument and Cardholder Attribution independently with explicit unknown values. Spend Category form the acyclic hierarchy defined by DD-LEDGER-CATEGORY-HIERARCHY and each transaction has at most one active Category Assignment. Give each transaction explicit unassigned or one active pool under the v1 assumption, with append-only corrections and no inference across dimensions.


## Rationale

These dimensions answer different questions. Stable local identity protects privacy and lets Hermes map provider wording without making the provider authoritative. Explicit unknown and unassigned states fail closed.

## Alternatives

Rejected deriving pool from account or cardholder, encoding pools as categories, using provider IDs as primary identity, and silent assignment inheritance.

## Consequences

Actuals support direct category totals, current-hierarchy subtree totals, pool totals, and a pool-by-category matrix without double counting. BUDGET may reference stable category nodes but owns plan semantics. OQ-LEDGER-15 must validate one-active-pool cardinality before implementation; mixed-pool evidence requires PRD and design revision.
