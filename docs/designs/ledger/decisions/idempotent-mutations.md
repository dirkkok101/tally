**Ref Code:** DD-LEDGER-IDEMPOTENT-MUTATIONS

## Description

Prevent duplicate finance effects across retries, crashes, evidence re-registration, and Reconciliation Decision.

## Decision

Commit each mutation outcome and its IdempotencyRecord in the same database transaction. The same key and canonical request returns the original result; a changed request conflicts. Additionally enforce stable logical identities for evidence, approved statement scopes, and Reconciliation Decision so different request keys cannot duplicate one real effect. Statement-scope identity is account plus inclusive period: identical canonical cross-key replay returns the existing scope, while changed manifest reference or evidence membership conflicts. Reconcile filesystem artifacts against committed database state on retry.

## Rationale

Request replay protection alone cannot prevent duplicate evidence arriving through another orchestration attempt. Logical uniqueness plus atomic outcomes protects the canonical ledger.

## Alternatives

Rejected best-effort caller deduplication, transport message IDs as authority, after-commit idempotency writes, and treating every statement replay as a new transaction.

## Consequences

Contracts define canonical request fingerprints and logical identity keys. Identical logical evidence, approved scope, or reconciliation effect under another request key returns the existing result; changed content, scope membership, or finance facts conflict. Backup and activation artifacts use the same reconciliation rule around durable commits.
