# Provider-neutral self-describing contract with optional guidance

> Generated from the lex graph. Do not edit this file as source of truth; update graph entities and re-export.

**Status:** accepted
**Status Notes:** Replaces executable-owned skill dependency with a provider-neutral authoritative schema and optional versioned guidance.
**Ref Code:** DD-LEDGER-SKILL-COMPATIBILITY

## Description

Define how automation discovers and uses LEDGER without making any agent product or skill installation authoritative.

## Decision

Make the executable operation registry and versioned JSON schemas the complete public contract. Optionally embed version-matched guidance bundles for supported agent hosts, installed only by explicit command. Core workflows require no skill and public schemas contain no provider or transport vocabulary.

## Rationale

Tally must be provider-neutral while remaining easy for automation to use. Schema-first discovery prevents documentation bundles from drifting into a second authority.

## Alternatives

Rejected provider-specific public contracts, mandatory Codex or Claude skills, network-fetched instructions, and direct Hermes adapters inside LEDGER.

## Consequences

Guidance compatibility is testable but optional. Unsupported callers can rely solely on schema and stable operation semantics. Guidance cannot broaden capabilities or bypass validation.
