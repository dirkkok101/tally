# Materialized coherent snapshots for dimensional actuals

**Status:** accepted

**Ref Code:** DD-LEDGER-SNAPSHOT-ACTUALS

## Description

Guarantee stable cross-process pagination and exact totals over mutable ledger projections.

## Decision

Materialize the first page and full-set totals under one immediate transaction from facts, relationships, evidence, reconciliation, category, pool, instrument, and cardholder state. Order by Effective Date then transaction ULID. Later pages read only the opaque snapshot cursor. Exclude snapshots from Durable Ledger State and backups.

## Rationale

Process invocations cannot hold database read transactions across pages. A committed ephemeral snapshot preserves one coherent result and exact pool/category totals.

## Alternatives

Rejected offset pagination over live rows, long-lived cross-process transactions, caller-maintained cursors, and pre-aggregated budget-owned totals.

## Consequences

First-page queries briefly use the single writer and may return busy. Evidence-only reconciliation changes state but not money; a statement-authoritative correction changes the active financial projection through an attributable replacement and therefore later snapshots may change current movement, spend, dates, and hierarchy groups. Each snapshot remains internally coherent and cites its generation and category-hierarchy fingerprints.
