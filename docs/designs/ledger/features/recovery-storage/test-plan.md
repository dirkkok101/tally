## E2E

### Edge

#### Reproduce complete Durable Ledger State

**Ref Code:** TC-LEDGER-VERIFIED-RECOVERY-DRILL
**Surface:** persistence
**Automation:** automated
**Status:** planned
**Owner:** LEDGER implementation

##### Preconditions

Representative Ledger containing every durable state type, including category hierarchy/moves, evidence, exact and corrected statement reconciliation, replacement, dimension carry-forward or unknown initialization, relationship replacement, exceptions, pools, payment attribution, assigned/unassigned cases, active/retired history, and exact baselines.

##### Steps

Create and verify a backup; restore into an empty generation; compare manifests, counts, hierarchy ancestry, transaction/dimension/relationship replacement chains, evidence/decision links, assignments, exact direct/subtree/pool totals, history, cardinality, and idempotency; activate; repeat with corrupt, cyclic, incomplete, incompatible, and faulted candidates.

##### Expected

A valid restore reproduces the complete authoritative current and historical state exactly; invalid hierarchy, replacement, carry-forward, link, total, permission, checksum, schema, or policy state fails before activation and leaves the prior generation current.

**Surface:** contract
**Automation:** automated
**Status:** planned
**Owner:** LEDGER implementation

##### Preconditions

Published executable on a supported protected-volume host plus canary descriptions, raw evidence and provider payloads, mailbox and messaging content, identifiers, credentials, and structured financial payloads.

##### Steps

### Edge

#### Prove mutation crash atomicity and idempotency

**Ref Code:** TC-LEDGER-ATOMIC-CRASH-RECOVERY
**Surface:** persistence
**Automation:** automated
**Status:** planned
**Owner:** LEDGER implementation

##### Preconditions

Temporary real SQLite generation with representative transactions, evidence, reconciliation, payment and pool attribution, corrections, relationships, idempotency outcomes, and an injectable activation adapter.

##### Steps

Inject termination or failure before and after each SQL commit, evidence or decision link, artifact publication, manifest write, candidate verification, and CURRENT replacement; restart, inspect integrity and exact grouped totals, and replay the same request.

##### Expected

Each restart sees exactly one complete committed effect or unchanged pre-operation state; no partial transaction, evidence, decision, attribution, assignment, relationship, scope, or artifact exists; replay returns the original stable outcome.
