#### Verify preserve query snapshots across pages contract

**Ref Code:** TC-LEDGER-SNAPSHOT-PAGINATION-CONTRACT
**Surface:** contract
**Automation:** automated
**Status:** planned
**Owner:** LEDGER implementation

##### Preconditions

A fresh representative local Ledger and the valid and invalid inputs required by FR-LEDGER-SNAPSHOT-PAGINATION are available.

##### Steps

1. Seed a representative real SQLite Ledger.
2. Start a first-page actuals query while a competing writer owns the lock; assert LEDGER-SNAPSHOT-BUSY and no cursor.
3. Retry after release; inject cancellation/crash before commit and assert no usable cursor or partial snapshot.
4. Complete the first page, capture items, exact full-set totals, cursor, and expiry.
5. Commit financial corrections in another process.
6. Fetch every later page using cursor only.
7. Exercise changed-filter, expired, malformed, incompatible-version, and stale-generation cursors.

##### Expected

The first page reads, computes, and materializes in one BEGIN IMMEDIATE transaction and emits no cursor before commit. Busy and pre-commit failure leave no partial snapshot. Later pages are read-only and reproduce the committed projection and exact totals despite intervening writes. Every invalid cursor condition returns its documented stable error, satisfying every FR-LEDGER-SNAPSHOT-PAGINATION acceptance criterion.
