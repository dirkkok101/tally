## Purpose

**AI Summary**: Entity-to-DTO mapping uses a DI-registered `{Entity}DTOMapper` class with primary constructor, following Capstone's pattern. The mapper has `Map(Entity entity, ...)` and `Map(IList<Entity> entities, ...)` methods (single + batch). It is a pure transformer — it NEVER queries the database. All data is received as parameters. `TranslationService` is injected via **primary constructor**; `requestLanguageId` and `defaultLanguageId` are passed as method parameters. Batch input uses ...

## Translation Support

Actions uses translations from day one, following Capstone's multilingual pattern. Entities that implement `ITranslatedEntity<T>` have translations resolved in the mapper via `TranslationService`.

### TranslationService Methods Used in Mappers

| Method | Purpose | Returns |
|--------|---------|---------|
| `GetEntityTranslation(entity, requestLangId, defaultLangId)` | Resolve translated Name/Description with fallback chain | Single `TEntityTranslation` |
| `BuildTranslatedValues(translations, requestLangId, selector)` | Build all OTHER language values for translation editing UI | `List<TranslatedValueDTO>` |

**Fallback chain** for `GetEntityTranslation`: request language -> default language -> first available -> placeholder `"!! No translated value !!"`.

### Translation Parameters

`TranslationService` is injected via **primary constructor** (matching Capstone's pattern). Language IDs are passed as method parameters:

```csharp
public class ActionDTOMapper(TranslationService translationService)
{
    public ActionDTO Map(
        ActionEntity entity,
        Guid requestLanguageId,
        Guid defaultLanguageId)
}
```

The endpoint resolves `requestLanguageId` and `defaultLanguageId` from the `TenantEndpoint` base class (`RequestLanguageId`, `DefaultLanguageId`) and passes them through. The mapper never resolves languages itself.

## Simple Mapper (Most Common)

Most Actions mappers are simple: entities are loaded with Include() where needed and the DTOMapper class transforms to DTO. Translated fields use TranslationService to resolve the correct language.

```csharp
public class ActionDTOMapper(TranslationService translationService)
{
    public ActionDTO Map(
        ActionEntity entity,
        Guid requestLanguageId,
        Guid defaultLanguageId)
    {
        var translation = translationService.GetEntityTranslation(
            entity, requestLanguageId, defaultLanguageId);

        return new ActionDTO
        {
            Id = entity.Id,
            Name = translation.Name,
            Description = translation.Description,
            Slug = entity.Slug,
            ActionTypeCode = entity.ActionTypeCode,
            ActionTypeName = entity.ActionTypeNameSnapshot,
            Status = new EnumDTO
            {
                Id = (int)entity.Status,
                Name = entity.Status.ToString(),
            },
            TranslatedNames = translationService.BuildTranslatedValues(
                entity.Translations, requestLanguageId, t => t.Name),
            TranslatedDescriptions = translationService.BuildTranslatedValues(
                entity.Translations, requestLanguageId, t => t.Description ?? string.Empty),
            CreatedDate = entity.CreatedDate,
        };
    }

    public IList<ActionDTO> Map(
        IList<ActionEntity> entities,
        Guid requestLanguageId,
        Guid defaultLanguageId)
    {
        return entities
            .Select(e => Map(e, requestLanguageId, defaultLanguageId))
            .ToList();
    }

    public ActionGridItemDTO MapGridItem(
        ActionEntity entity,
        Guid requestLanguageId,
        Guid defaultLanguageId)
    {
        var translation = translationService.GetEntityTranslation(
            entity, requestLanguageId, defaultLanguageId);

        return new ActionGridItemDTO
        {
            Id = entity.Id,
            Name = translation.Name,
            Slug = entity.Slug,
            ActionTypeCode = entity.ActionTypeCode,
            ActionTypeName = entity.ActionTypeNameSnapshot,
            StatusName = entity.Status.ToString(),
        };
    }
}
```

Catalogue display fields come from the loaded entity, snapshot fields, or a preloaded DTOMapperDataContext. The DTOMapper never translates stale enum aliases or queries catalogue tables on its own.

## Mapper with Direct Parameter (1 extra type)

When the mapper needs one additional data type beyond the entity, pass it as a method parameter alongside the language IDs:

```csharp
// Features/Workflows/Shared/Mappers/WorkflowDTOMapper.cs

public class WorkflowDTOMapper(TranslationService translationService)
{
    public WorkflowDTO Map(
        Workflow entity,
        Guid requestLanguageId,
        Guid defaultLanguageId,
        IList<TriggerType> triggerTypes)
    {
        var translation = translationService.GetEntityTranslation(
            entity, requestLanguageId, defaultLanguageId);

        var triggers = entity.Triggers
            .Select(t => triggerTypes.FirstOrDefault(tt => tt.Id == t.TriggerTypeId))
            .Where(tt => tt is not null)
            .Select(tt => new NamedDTO
            {
                Id = tt!.Id,
                Name = tt.Code,
                Description = tt.DisplayName,
            })
            .ToList();

        return new WorkflowDTO
        {
            Id = entity.Id,
            Name = translation.Name,
            Description = translation.Description,
            Triggers = triggers,
            StepCount = entity.Steps.Count,
            CreatedDate = entity.CreatedDate,
        };
    }

    public IList<WorkflowDTO> Map(
        IList<Workflow> entities,
        Guid requestLanguageId,
        Guid defaultLanguageId,
        IList<TriggerType> triggerTypes)
    {
        return entities
            .Select(e => Map(e, requestLanguageId, defaultLanguageId, triggerTypes))
            .ToList();
    }
}
```

## Mapper with DTOMapperDataContext (2+ extra types)

When the mapper needs multiple additional data types, use the [DTOMapperDataContext](data-context.md) pattern. The `Map` method accepts translation parameters and the context:

```csharp
// Features/ComplianceProfiles/Shared/Mappers/ComplianceProfileDTOMapper.cs

public class ComplianceProfileDTOMapper(TranslationService translationService)
{
    public ComplianceProfileDTO Map(
        ComplianceProfile entity,
        Guid requestLanguageId,
        Guid defaultLanguageId,
        ComplianceProfileDTOMapperDataContext context)
    {
        var translation = translationService.GetEntityTranslation(
            entity, requestLanguageId, defaultLanguageId);

        return new ComplianceProfileDTO
        {
            Id = entity.Id,
            Name = translation.Name,
            Description = translation.Description,
            Actions = entity.ProfileActions
                .Where(pa => context.ActionMap.ContainsKey(pa.ActionId))
                .Select(pa => new NamedDTO
                {
                    Id = pa.ActionId,
                    Name = context.ActionMap[pa.ActionId].Name,

                .ToList(),
            RequiredApprovals = context.RequiredApprovals,
        };

    public IList<ComplianceProfileDTO> Map(
        IList<ComplianceProfile> entities,
        Guid requestLanguageId,
        Guid defaultLanguageId,
        ComplianceProfileDTOMapperDataContext context)
    {
        return entities
            .Select(e => Map(e, requestLanguageId, defaultLanguageId, context))
            .ToList();

}
```

## DTO Field Type Mapping ([ADR-0005](../../adr/0005-enumdto-nameddto-for-ui-binding.md))

DTO fields that represent true enums or FK/catalogue references use structured types for zero-transformation UI binding, but the ownership model matters.

| Entity Field Type | DTO Field Type | Example |
|-------------------|---------------|---------|
| C# enum (system-owned state) | EnumDTO | new EnumDTO { Id = (int)entity.Status, Name = entity.Status.ToString() } |
| FK Guid with navigation property | NamedDTO | new NamedDTO { Id = entity.WorkflowId, Name = entity.Workflow?.Name ?? string.Empty } |
| Tenant catalogue code | string Code plus display field or lookup DTO | ActionTypeCode = entity.ActionTypeCode |
| Translated string | Resolved via TranslationService | Name = translation.Name |
| Translated field alternatives | List<TranslatedValueDTO> | translationService.BuildTranslatedValues(...) |
| Scalar | Direct mapping | Slug = entity.Slug |
| Collection of entities | List<ChildDTO> | .Select(c => mapper.Map(c, reqLang, defLang)).ToList() |

```csharp
// CORRECT - true enum field uses EnumDTO
Status = new EnumDTO
{
    Id = (int)entity.Status,
    Name = entity.Status.ToString(),
},

// CORRECT - FK reference uses NamedDTO
Workflow = new NamedDTO
{
    Id = entity.WorkflowId,
    Name = entity.Workflow?.Name ?? string.Empty,
},

// CORRECT - tenant catalogue reference exposes stable code/display data
ActionTypeCode = entity.ActionTypeCode,
ActionTypeName = entity.ActionTypeNameSnapshot,

// WRONG - configurable catalogue as local enum alias
ActionType = new EnumDTO { Id = 1, Name = "Corrective" },
```

Grid items are flat by design and may use scalar display fields such as StatusName or ActionTypeName because they are read-only projections. Full roundtrip DTOs still keep enough structure for save without frontend transformation.

## Mapping Methods Per DTO Shape

Each entity DTOMapper provides dedicated methods for each DTO shape:

| DTO Shape | Method | Purpose | Used By |
|-----------|--------|---------|---------|
| Full DTO | `Map()` | Complete entity representation with translated alternatives | Get single endpoint |
| Grid item DTO | `MapGridItem()` | Flat, lightweight for lists (translated name, no alternatives) | GetGridList endpoint |
| Lookup DTO | `MapLookup()` | Minimal (Id + translated Name) for dropdowns | Lookup endpoint |

Each method also has a batch overload accepting `IList<Entity>` and returning `IList<DTO>`:

```csharp
// CORRECT — Separate methods for each shape, with single + batch overloads
public ActionDTO Map(ActionEntity entity, Guid reqLang, Guid defLang) { ... }
public IList<ActionDTO> Map(IList<ActionEntity> entities, Guid reqLang, Guid defLang) { ... }
public ActionGridItemDTO MapGridItem(ActionEntity entity, Guid reqLang, Guid defLang) { ... }
public IList<ActionGridItemDTO> MapGridItem(IList<ActionEntity> entities, Guid reqLang, Guid defLang) { ... }
public ActionLookupDTO MapLookup(ActionEntity entity, Guid reqLang, Guid defLang) { ... }

// WRONG — Conditional logic in one method
public object Map(ActionEntity entity, string shape) { ... }
```

**Full DTOs** include `TranslatedNames` and `TranslatedDescriptions` (via `BuildTranslatedValues`) for the translation editing UI. Grid and lookup DTOs only include the resolved translated value for the request language.

## Correct vs Wrong

### DI-registered mapper class vs static extension methods

```csharp
// CORRECT — DI-registered DTOMapper class, TranslationService via primary constructor
public class ActionDTOMapper(TranslationService translationService)
{
    public ActionDTO Map(ActionEntity entity,
        Guid requestLanguageId,
        Guid defaultLanguageId) { ... }

    public IList<ActionDTO> Map(IList<ActionEntity> entities,
        Guid requestLanguageId,
        Guid defaultLanguageId) { ... }
}

// Endpoint injects and calls:
await Send.OkAsync(actionDTOMapper.Map(entity, reqLang, defLang), ct);

// WRONG — Static extension methods
public static class ActionMapperExtensions
{
    public static ActionDTO ToDTO(this ActionEntity entity,
        Guid requestLanguageId,
        Guid defaultLanguageId) { ... }
}

// WRONG — Extension method call site
await Send.OkAsync(entity.ToDTO(reqLang, defLang), ct);
```

### Pure transformer vs querying mapper

```csharp
// CORRECT — Mapper receives all data as parameters
public ComplianceProfileDTO Map(ComplianceProfile entity,
    Guid reqLang, Guid defLang, ComplianceProfileDTOMapperDataContext context)
{
    // Uses context.ActionMap — pre-loaded by DTOMapperDataContextService
    Actions = entity.ProfileActions
        .Where(pa => context.ActionMap.ContainsKey(pa.ActionId))
        .Select(pa => new NamedDTO { Id = pa.ActionId, Name = context.ActionMap[pa.ActionId].Name })
        .ToList(),
}

// WRONG — Mapper queries the database
public async Task<ComplianceProfileDTO> MapAsync(ComplianceProfile entity, ActionsDbContext db)
{
    // NEVER query inside a mapper
    var actions = await db.Actions.Where(a => entity.ProfileActions.Select(pa => pa.ActionId).Contains(a.Id)).ToListAsync();
}
```

### Batch mapping via instance method vs LINQ

```csharp
// CORRECT — Dedicated batch method on the DTOMapper class
public IList<ActionDTO> Map(IList<ActionEntity> entities,
    Guid reqLang, Guid defLang)
{
    return entities.Select(e => Map(e, reqLang, defLang)).ToList();
}

// WRONG — Callers manually doing LINQ at the call site
var items = entities.Select(e => actionDTOMapper.Map(e, reqLang, defLang)).ToList();
```

### Null-safe navigation property access

```csharp
// CORRECT — Defensive with null-conditional and fallback
Action = new NamedDTO
{
    Id = entity.ActionId,
    Name = entity.Action?.Name ?? string.Empty,
},

// WRONG — Assumes navigation property is loaded
Action = new NamedDTO
{
    Id = entity.ActionId,
    Name = entity.Action.Name,  // NullReferenceException if not included
},
```

## Rules

### MUST

1. **Use a DI-registered DTOMapper class** — `{Entity}DTOMapper` with primary constructor, registered as `AddScoped`
2. **Provide single + batch `Map` overloads** — `Map(Entity)` and `Map(IList<Entity>)` for each DTO shape, with `IList<T>` for both input and return
3. **Never query in the mapper** — receive all data as parameters
4. **Inject `TranslationService` via primary constructor** (matching Capstone); pass `requestLanguageId`, `defaultLanguageId` as method parameters
5. **Resolve translated fields via `TranslationService.GetEntityTranslation()`** — never read raw entity properties for translatable Name/Description
6. **Include `TranslatedNames`/`TranslatedDescriptions`** on full DTOs via `BuildTranslatedValues()` for translation editing UI
7. **Handle null navigation properties** — use `?.` and `?? string.Empty`
8. **Use `EnumDTO` for enum fields and `NamedDTO` for FK references** on full DTOs ([ADR-0005](../../adr/0005-enumdto-nameddto-for-ui-binding.md))
9. **Place DTO types in `Nxgn.Actions.Contracts/{Entity}/`** — never in `Features/`
10. **Use ALL CAPS `DTO` suffix** — `ActionDTO`, not `ActionDto`
11. **DTOs are classes** with `{ get; set; }`

### SHOULD

1. **Provide all three mapping method sets** — `Map()`, `MapGridItem()`, `MapLookup()` for entities exposed through CRUD endpoints
2. **Keep mappers stateless** — the DTOMapper class has no mutable state; it is a pure transformer
3. **Use [DTOMapperDataContext](data-context.md)** when 2+ additional data types are needed
4. **Sort child collections** in a deterministic order (e.g., by Name, by Code)
5. **Map nested translated entities** using the same `TranslationService` and language IDs passed to the parent

### MUST NOT

1. **Query the database** from within a mapper
2. **Use static extension methods** for entity-to-DTO mapping — use DI-registered DTOMapper classes
3. **Modify entities** during mapping
4. **Use `async` in mappers** — if data loading is needed, it belongs in the endpoint or DTOMapperDataContextService
5. **Read raw entity properties for translatable fields** — always go through `TranslationService`

## Departure from Capstone: Combined Mapper Class

Capstone uses a **separate** `{Entity}GridRowDTOMapper` class for grid row mapping. Actions combines all DTO shapes into a single `{Entity}DTOMapper` class with separate methods (`Map()`, `MapGridItem()`, `MapLookup()`). This reduces file count — one mapper class per entity instead of two or three.

| Capstone | Actions |
|----------|---------|
| `{Entity}DTOMapper.cs` — full DTO only | `{Entity}DTOMapper.cs` — `Map()`, `MapGridItem()`, `MapLookup()` |
| `{Entity}GridRowDTOMapper.cs` — grid row only | Combined into same class above |
