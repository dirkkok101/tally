## The Core Principle

> **One `IEntityTypeConfiguration<T>` class per entity.** Auto-discovered via `ApplyConfigurationsFromAssembly()`. No manual registration, no static extension methods on ModelBuilder. (ADR-0018)

## Reference Configuration

```csharp
// Data/Configuration/ActionEntityConfiguration.cs
public class ActionEntityConfiguration : IEntityTypeConfiguration<ActionEntity>
{
    public void Configure(EntityTypeBuilder<ActionEntity> entity)
    {
        entity.ToTable("Actions", "actions");
        entity.HasKey(e => e.Id);
        entity.ConfigureTrackedEntity();
        entity.ConfigureTenantEntity();

        // Properties
        entity.Property(e => e.ReferenceNumber)
            .HasMaxLength(50)
            .IsRequired();
        entity.Property(e => e.Status)
            .HasConversion<string>()    // ADR-0004: enum stored as string
            .HasMaxLength(50)
            .IsRequired();
        entity.Property(e => e.Priority)
            .HasConversion<string>()
            .HasMaxLength(50)
            .IsRequired();
        entity.Property(e => e.Version).IsConcurrencyToken();

        // Soft delete
        entity.Property(e => e.IsDeleted).HasDefaultValue(false);
        entity.HasQueryFilter(e => !e.IsDeleted);

        // Relationships
        entity.HasOne(e => e.WorkflowDefinition)
            .WithMany(w => w.Actions)
            .HasForeignKey(e => e.WorkflowDefinitionId)
            .OnDelete(DeleteBehavior.Restrict);

        entity.HasOne(e => e.CurrentState)
            .WithMany()
            .HasForeignKey(e => e.CurrentStateId)
            .OnDelete(DeleteBehavior.SetNull);

        // Indexes
        entity.HasIndex(e => new { e.TenantId, e.ReferenceNumber }).IsUnique();
        entity.HasIndex(e => e.Status);
    }
}
```

### Configuration Order

Within each `Configure()` method, follow this order:

1. `ToTable()` — table name and schema
2. `HasKey()` — primary key
3. `ConfigureTrackedEntity()` / `ConfigureTenantEntity()` — shared helpers
4. Properties — `HasConversion`, `HasMaxLength`, `IsRequired`, `HasColumnType`
5. Soft delete — `HasDefaultValue`, `HasQueryFilter`
6. Concurrency — `IsConcurrencyToken`
7. Relationships — `HasOne`/`HasMany` with explicit `OnDelete`
8. Indexes — `HasIndex` with uniqueness and filters

public static class SharedConfiguration
{
    public static void ConfigureTrackedEntity<T>(this EntityTypeBuilder<T> entity)
        where T : TrackedEntity
    {
        entity.Property(e => e.CreatedDate).IsRequired();
        entity.Property(e => e.CreatedById).IsRequired();
    }

    public static void ConfigureTenantEntity<T>(this EntityTypeBuilder<T> entity)
        where T : class, ITenantEntity

        // Marks TenantId as required. Each entity configuration MUST explicitly
        // configure the tenant relationship if a navigation property exists,

    }
}

## Configuration Rules

### Table and Column Naming

| Convention | Detail |
|-----------|--------|
| **Table names** | PascalCase in `actions` schema: `entity.ToTable("Actions", "actions")` |
| **Column names** | PascalCase (EF Core defaults) — do NOT use `.HasColumnName()`. Let EF Core use property names as column names. |

### TrackedEntity and Tenant

| Convention | Detail |
|-----------|--------|
| **TrackedEntity fields** | Call `entity.ConfigureTrackedEntity()` — marks `CreatedDate`, `CreatedById` as required |
| **Tenant column** | Call `entity.ConfigureTenantEntity()` — marks `TenantId` as required |

### Soft Delete

For entities implementing `ISoftDeletable`, configure the global query filter:

```csharp
entity.Property(e => e.IsDeleted).HasDefaultValue(false);
entity.HasQueryFilter(e => !e.IsDeleted);
```

To query including soft-deleted records, use `IgnoreQueryFilters()` on the IQueryable.

### Optimistic Concurrency

For entities implementing `IVersioned`, configure the concurrency token:

```csharp
entity.Property(e => e.Version).IsConcurrencyToken();
```

EF Core will automatically include `Version` in the `WHERE` clause of `UPDATE` statements, throwing `DbUpdateConcurrencyException` on conflict.

### Delete Behavior

Every FK MUST specify `OnDelete(DeleteBehavior.*)` explicitly:

| Rule | When | Example |
|------|------|---------|
| `Cascade` | Owned child collections within same aggregate | WorkflowDefinition -> WorkflowStates, ActionEntity -> ActionEvidence |
| `Restrict` | Cross-aggregate references, prevents accidental data loss | ActionEntity -> WorkflowDefinition, EscalationRule -> ComplianceProfile |
| `SetNull` | Optional FKs where parent deletion is allowed | ActionEntity.CurrentStateId -> WorkflowState |

```csharp
// Correct — explicit delete behavior on every FK
entity.HasOne(e => e.WorkflowDefinition)
    .WithMany(w => w.Actions)
    .HasForeignKey(e => e.WorkflowDefinitionId)
    .OnDelete(DeleteBehavior.Restrict);

// Wrong — missing OnDelete (EF Core defaults vary and are unsafe)
entity.HasOne(e => e.WorkflowDefinition)
    .WithMany(w => w.Actions)
    .HasForeignKey(e => e.WorkflowDefinitionId);
```

### Indexes

| Pattern | When | Example |
|---------|------|---------|
| **Unique composite** | Data integrity for tenant-scoped uniqueness | `(TenantId, ReferenceNumber)`, `(TenantId, Code)` |
| **Unique single** | Global uniqueness | `Code`, `Slug` |
| **Filtered (partial)** | Active/non-deleted records | `WHERE "IsDeleted" = false`, `WHERE "IsActive" = true` |
| **Covering** | Frequent query patterns | `(TenantId, Status)`, `(WorkflowDefinitionId, Status)` |

```csharp
// Unique composite — tenant-scoped uniqueness
entity.HasIndex(e => new { e.TenantId, e.ReferenceNumber }).IsUnique();

// Filtered index — only index active records
entity.HasIndex(e => e.Code)
    .HasFilter("\"IsActive\" = true");

// Covering index for common query pattern
entity.HasIndex(e => new { e.TenantId, e.Status });
```

### Array Columns

For `string[]` or `string[]?` properties, use PostgreSQL native array type:

```csharp
// Entity property
public string[]? Tags { get; set; }

// EF Configuration
entity.Property(e => e.Tags)
    .HasColumnType("text[]");
```

PostgreSQL arrays support `Contains()`, `Any()`, and `@>` (array containment) in LINQ queries.

### Default Values

Use `HasDefaultValue()` for simple defaults and `HasDefaultValueSql()` for SQL expressions:

```csharp
// Simple default
entity.Property(e => e.IsActive).HasDefaultValue(true);
entity.Property(e => e.IsDeleted).HasDefaultValue(false);

// SQL expression default (timestamps, empty JSON, generated values)
entity.Property(e => e.CreatedDate).HasDefaultValueSql("now()");
entity.Property(e => e.Configuration).HasDefaultValueSql("'{}'::jsonb");
```

**Rule:** Only use `HasDefaultValueSql()` when the default must be computed at the database level (e.g., `now()`, UUID generation). For static values, prefer `HasDefaultValue()` or C# property initializers.

### JsonDocument Columns

For `JsonDocument` properties, configure with JSONB column type and a value comparer:

```csharp
entity.Property(e => e.Configuration)
    .HasColumnType("jsonb")
    .HasDefaultValueSql("'{}'::jsonb")
    .HasConversion(
        v => JsonSerializer.Serialize(v, (JsonSerializerOptions?)null),
        v => JsonDocument.Parse(v, default))
    .Metadata.SetValueComparer(
        new ValueComparer<JsonDocument>(
            (a, b) => JsonDocument.Parse(a!.RootElement.GetRawText(), default)
                .RootElement.GetRawText() ==
                JsonDocument.Parse(b!.RootElement.GetRawText(), default)
                .RootElement.GetRawText(),
            v => v.RootElement.GetRawText().GetHashCode(),
            v => JsonDocument.Parse(v.RootElement.GetRawText(), default)));
```

### Translation Tables

For entities implementing `ITranslatedEntity<T>`, create a dedicated `IEntityTypeConfiguration<T>`:

```csharp
// Data/Configuration/WorkflowDefinitionTranslationConfiguration.cs
public class WorkflowDefinitionTranslationConfiguration : IEntityTypeConfiguration<WorkflowDefinitionTranslation>
{
    public void Configure(EntityTypeBuilder<WorkflowDefinitionTranslation> entity)
    {
        entity.ToTable("WorkflowDefinitionTranslations", "actions");
        entity.HasKey(e => e.Id);
        entity.ConfigureTrackedEntity();
        entity.ConfigureTenantEntity();

        entity.Property(e => e.Name).HasMaxLength(250).IsRequired();
        entity.Property(e => e.Description).HasColumnType("text");
        entity.Property(e => e.LanguageId).IsRequired();

        // Composite unique: one translation per entity per language per tenant
        entity.HasIndex(e => new { e.WorkflowDefinitionId, e.LanguageId, e.TenantId }).IsUnique();

        entity.HasOne<WorkflowDefinition>()
            .WithMany(w => w.Translations)
            .HasForeignKey(e => e.WorkflowDefinitionId)
            .OnDelete(DeleteBehavior.Cascade);

        entity.HasOne(e => e.Language)
            .WithMany()
            .HasForeignKey(e => e.LanguageId)
            .OnDelete(DeleteBehavior.Restrict);
    }
}
```

## DbContext Registration

All `IEntityTypeConfiguration<T>` classes are auto-discovered and applied via `ApplyConfigurationsFromAssembly()`:

```csharp
// Data/ActionsDbContext.cs
protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    modelBuilder.HasDefaultSchema("actions");

    // Auto-discover and apply all IEntityTypeConfiguration<T> classes in this assembly
    modelBuilder.ApplyConfigurationsFromAssembly(typeof(ActionsDbContext).Assembly);
}
```

## RLS (Row-Level Security)

Tenant isolation is enforced at the PostgreSQL level via RLS policies on `TenantId`. Unlike Identity (which uses a narrow RLS boundary per ADR-0002), Actions applies RLS to ALL tenant-scoped tables.

### How RLS Gets the Tenant Context

The tenant context flows from JWT to database connection in three steps:

1. **TenantEndpoint** extracts `TenantId` from JWT claims and sets it on `EffectiveTenantProvider` (a scoped service)
2. **TenantConnectionInterceptor** (an EF `DbConnectionInterceptor`) runs `SET LOCAL app.tenant_id = '{tenantId}'` when a connection is opened
3. **PostgreSQL RLS policies** filter all queries on tenant-scoped tables using `current_setting('app.tenant_id')::uuid`

```
JWT Bearer token → TenantEndpoint.HandleAsync()
    → EffectiveTenantProvider.TenantId = tenantId     (scoped DI)
    → IDbContextFactory creates ActionsDbContext
    → TenantConnectionInterceptor.ConnectionOpenedAsync()
    → SET LOCAL app.tenant_id = '{tenantId}'           (PostgreSQL session variable)
    → RLS policy: WHERE "TenantId" = current_setting('app.tenant_id')::uuid
```

This is why queries never filter by `TenantId` in application code — the database does it automatically. It is also why `IDbContextFactory` is required instead of injecting `ActionsDbContext` directly: each factory-created context gets the interceptor with the current tenant.

### Key Implications

| Rule | Detail |
|------|--------|
| **All ITenantEntity tables** | Have RLS policies — visible only to the current tenant context |
| **No tenant filtering in code** | Application queries never filter by TenantId — RLS handles it |
| **Cross-tenant reads** | Require `EnablePlatformAdminBypass()` scoped with `using` |
| **Cross-tenant writes** | Require a new `IServiceScope` with tenant override — never use bypass for writes |
| **Platform-level tables** | Tables without `ITenantEntity` (e.g., `Languages`) have no RLS |
| **Integration tests** | Must set `app.tenant_id` on the test connection — or use the `TestTenantProvider` helper |

**Critical**: `EnablePlatformAdminBypass()` returns `IDisposable` — ALWAYS scope with `using` around SELECT queries only. Leaving bypass active during writes causes `DbUpdateConcurrencyException` because `SET LOCAL` prefix confuses Npgsql's affected row count parsing.

## Departures from Capstone

| Aspect | Capstone | Actions | Why |
|--------|----------|---------|-----|
| **Configuration style** | Static extension methods on `ModelBuilder` | `IEntityTypeConfiguration<T>` with `ApplyConfigurationsFromAssembly()` | ADR-0018: per-entity configuration classes are self-contained and auto-discovered |
| **Tenant isolation** | Application-level filtering in queries | PostgreSQL RLS policies on `TenantId` | Database-enforced isolation is stronger |
| **RLS scope** | Varies by table | ALL tenant-scoped tables | Actions enforces RLS universally, no narrow boundary |
| **Entity location** | `Database/Model/Entities/{Feature}/` | `Data/Entities/` (flat) | Flat layout preferred until entity count warrants grouping |
| **Schema** | Default schema | `actions` schema | Multi-service database with schema isolation |
| **DbContext** | Multiple bounded contexts | Single `ActionsDbContext` | Actions is a single bounded context |
| **Tenant column** | `TenantId` | `TenantId` | Same as Capstone |
