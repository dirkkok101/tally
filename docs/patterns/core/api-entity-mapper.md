## Purpose

**AI Summary**: Entity mappers are DI-registered classes that transform inbound DTOs to entities. The mapper is a **pure transformer** — it resolves existing entities (by ID, then business key fallback), determines create vs update, maps DTO fields to entity properties, sets audit fields, handles translations via `TranslationService`, and returns `EntityMapperResult<T>`. It contains NO business logic, NO guards, NO cross-entity operations, and NEVER returns OneOf/Conflict/NotFound. All busine...

## Core Principle: Pure Transformer

```
EntityMapper = DTO → Entity field mapping + entity resolution (find or create) + translations
Command      = Business rules + guards + cross-entity ops + SaveChangesAsync

The mapper NEVER makes business decisions.
The command NEVER maps DTO fields to entity properties.
```

## Mapper vs Command Boundary

This boundary is the most important rule in the pattern. Violations create inconsistency across the codebase and make mappers untestable.

| Concern | Owner | Why |
|---------|-------|-----|
| DTO to Entity field mapping | **Mapper** | Pure data transformation |
| Entity resolution (ID lookup, business key fallback) | **Mapper** | Determines create vs update |
| Audit fields (CreatedDate/CreatedById, UpdatedDate/UpdatedById) | **Mapper** | Set from server context, never from DTO |
| Entity defaults (e.g., `IsActive = true`, `Status = Active`) | **Mapper** | Set on create for fields not on the DTO |
| Immutable field handling (skip on update, set on create) | **Mapper** | Comment why field is omitted on update |
| Translation handling (AddOrUpdateEntityTranslation) | **Mapper** | Translations are part of field mapping |
| `EntityMapperResult<T>` return | **Mapper** (always) | Command interprets the result |
| | | |
| Business rules (disabled-entity guard, duplicate check) | **Command** | Domain logic, not transformation |
| Cross-entity operations (create related entities) | **Command** | Mapper only maps entities of type T |
| TOCTOU / uniqueness catches (`DbUpdateException`) | **Command** | Wraps `SaveChangesAsync` |
| Child collection diffing | **Command** | Aggregate root management |
| `SaveChangesAsync` | **Command** | Persistence is the command's responsibility |
| Audit logging | **Command** or **Endpoint** | After successful persistence |
| FK validation (does referenced entity exist?) | **Command** | Business rule, not field mapping |

**Test:** If you're writing an `if` statement in a mapper that doesn't relate to "is this field null/empty" or "does this entity exist", it probably belongs in the command.

## Standard Signature

### Batch Primary (default)

```csharp
public async Task<EntityMapperResult<T>> MapAsync(
    List<SaveRequest> dtoList, Guid userId,
    Guid requestLanguageId, Guid defaultLanguageId,
    CancellationToken ct, ActionsDbContext? db = null)
```

### Single-DTO Convenience Overload

```csharp
public Task<EntityMapperResult<T>> MapAsync(
    SaveRequest dto, Guid userId,
    Guid requestLanguageId, Guid defaultLanguageId,
    CancellationToken ct, ActionsDbContext? db = null)
    => MapAsync([dto], userId, requestLanguageId, defaultLanguageId, ct, db);
```

| Parameter | Purpose |
|-----------|---------|
| `dtoList` | List of SaveRequests (inherits DTO) — the inbound data (batch primary) |
| `userId` | User performing the action — for audit fields |
| `requestLanguageId` | Caller's preferred language — for translations |
| `defaultLanguageId` | System default language — for translation fallback |
| `ct` | CancellationToken — propagate to all DB calls |
| `db` | Optional shared DbContext — mapper disposes only if it created one |

**No `tenantId`** — RLS handles tenant scoping. If the mapper needs tenant context for entity creation, the command passes it via the shared DbContext's `EffectiveTenantProvider`.

## Reference Implementation

`ActionEntityMapper` - scalar fields, catalogue codes, immutable fields, translations:

```csharp
public class ActionEntityMapper(
    IDbContextFactory<ActionsDbContext> dbContextFactory,
    TranslationService translationService)
{
    public async Task<EntityMapperResult<ActionEntity>> MapAsync(
        List<SaveActionRequest> dtoList,
        Guid userId,
        Guid requestLanguageId,
        Guid defaultLanguageId,
        CancellationToken ct,
        ActionsDbContext? db = null)
    {
        var disposeDb = db is null;
        db ??= await dbContextFactory.CreateDbContextAsync(ct);
        try
        {
            var result = new EntityMapperResult<ActionEntity>();
            var now = DateTime.UtcNow;

            foreach (var dto in dtoList)
            {
                var existing = dto.Id != Guid.Empty
                    ? await db.Actions.FindAsync([dto.Id], ct)
                    : null;

                if (existing is null)
                {
                    var entity = new ActionEntity
                    {
                        Id = Guid.CreateVersion7(),
                        Slug = dto.Slug,
                        ActionTypeCode = dto.ActionTypeCode.Trim().ToUpperInvariant(),
                        Status = (ActionStatus)dto.Status.Id,
                        IsActive = true,
                        CreatedDate = now,
                        CreatedById = userId,
                    };

                    translationService.AddOrUpdateEntityTranslation(
                        entity, requestLanguageId, dto.Name, dto.Description);

                    result.NewItems.Add(entity);
                }
                else
                {
                    existing.ActionTypeCode = dto.ActionTypeCode.Trim().ToUpperInvariant();
                    existing.Status = (ActionStatus)dto.Status.Id;
                    existing.UpdatedDate = now;
                    existing.UpdatedById = userId;

                    translationService.AddOrUpdateEntityTranslation(
                        existing, requestLanguageId, dto.Name, dto.Description);

                    result.UpdatedItems.Add(existing);
                }
            }

            return result;
        }
        finally
        {
            if (disposeDb) await db.DisposeAsync();
        }
    }
}
```

The command validates `ActionTypeCode` against active tenant catalogue records before the mapper runs. The mapper only copies the already accepted value.

## Lookup Strategy

### Simple: By ID only

Most Actions entities use ID-only lookup when the client knows the entity ID:

```csharp
var existing = dto.Id != Guid.Empty
    ? await db.Actions.FindAsync([dto.Id], ct)
    : null;
```

### With Business Key Fallback

For entities with a unique business key such as slug or code, the mapper can fall back to business key lookup when `Guid.Empty` is provided. This supports upsert-by-business-key:

```csharp
ActionEntity? existing = null;

if (dto.Id != Guid.Empty)
{
    existing = await db.Actions.FindAsync([dto.Id], ct);
}
else if (!string.IsNullOrEmpty(dto.Slug))
{
    existing = await db.Actions
        .FirstOrDefaultAsync(a => a.Slug == dto.Slug, ct);
}

if (existing is null)
{
    result.NewItems.Add(new ActionEntity { ... });
}
else
{
    existing.ActionTypeCode = dto.ActionTypeCode.Trim().ToUpperInvariant();
    result.UpdatedItems.Add(existing);
}
```

Business key lookup is entity resolution, not business logic. The mapper determines whether the entity already exists; it does not decide whether the caller may create or update it.

## Audit Fields

| Operation | Fields Set | Where |
|-----------|-----------|-------|
| Create (NewItems) | `CreatedDate = DateTime.UtcNow`, `CreatedById = userId` | Mapper |
| Update (UpdatedItems) | `UpdatedDate = DateTime.UtcNow`, `UpdatedById = userId` | Mapper |

Note: `UpdatedDate`/`UpdatedById` — **not** `ModifiedDate`/`ModifiedById`.

## Translation Handling

Actions uses translations from day one. Entities implementing `ITranslatedEntity<T>` have translations set in the mapper via `TranslationService`:

```csharp
// On create — adds a new translation for the request language
translationService.AddOrUpdateEntityTranslation(
    entity, requestLanguageId, dto.Name, dto.Description);

// On update — updates the translation for the request language
translationService.AddOrUpdateEntityTranslation(
    existing, requestLanguageId, dto.Name, dto.Description);
```

The `TranslationService` is injected via primary constructor. Language IDs (`requestLanguageId`, `defaultLanguageId`) are passed as method parameters.

## Enum and Catalogue Fields

True system enum fields on DTOs use `EnumDTO` ([ADR-0005](../../adr/0005-enumdto-nameddto-for-ui-binding.md)); the mapper reads `Id` and casts:

```csharp
Status = (ActionStatus)dto.Status.Id,
```

User-configurable catalogues are not enum fields. For tenant-owned lookup data such as Action Types or RCA Methods, the command validates the submitted `Code` or `Id` against the owning admin module records, and the mapper copies the accepted value:

```csharp
ActionTypeCode = dto.ActionTypeCode.Trim().ToUpperInvariant(),
```

Do not create compatibility mappers that translate stale enum aliases into catalogue records.

### Enum and Catalogue Fields Example 1

```csharp
Status = (ActionStatus)dto.Status.Id,
ActionTypeCode = dto.ActionTypeCode.Trim().ToUpperInvariant(),
```

## Common Mistakes

```csharp
// WRONG — Business logic in mapper (throws or returns error)
if (isProtected)
    throw new InvalidOperationException("Cannot modify protected entity");  // ← belongs in Command

// WRONG — Creating a different entity type in mapper

// WRONG — Error types in mapper return (OneOf, CommandResult, etc.)
```

## Rules

### MUST

1. Return `EntityMapperResult<T>` — never OneOf, never Conflict, never NotFound
2. Use batch-primary signature: `MapAsync(List<DTO> dtoList, Guid userId, Guid requestLanguageId, Guid defaultLanguageId, CancellationToken ct, ActionsDbContext? db = null)`
3. Provide single-DTO convenience overload that wraps in a list
4. Accept `CancellationToken ct` and propagate to all DB calls
5. Accept optional `ActionsDbContext? db = null` for shared context
6. Use `Guid.CreateVersion7()` for new entity IDs
7. Detect create vs update with `dto.Id == Guid.Empty`
8. Set `CreatedDate`/`CreatedById` on create, `UpdatedDate`/`UpdatedById` on update
9. Handle translations via `TranslationService.AddOrUpdateEntityTranslation`
10. Map scalar fields only — child collections belong in the Command
11. Dispose DbContext only if the mapper created it

### MUST NOT

1. Return `OneOf`, `Conflict`, `NotFound`, or any error type — the mapper is a pure transformer
2. Contain business logic (guards, permission checks, cross-entity validation)
3. Create entities of a different type than `T` (e.g., mapper for `ActionEntity` must not create `WorkflowStep`)
4. Call `SaveChangesAsync` — the Command handles persistence
5. Validate business rules — that belongs in validators or commands
6. Accept `tenantId` as a parameter — RLS handles tenant scoping

### SHOULD

1. Use business key fallback lookup when `Guid.Empty` is provided and entity has a unique business key
2. Comment immutable fields that are intentionally omitted from the update path
3. Set entity defaults (e.g., `IsActive = true`) in the create path for fields not on the DTO
