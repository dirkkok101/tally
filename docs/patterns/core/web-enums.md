## The Core Principle

> The API is the single source of truth for system enum display labels and dropdown options. The owning admin module is the single source of truth for tenant-configurable catalogue values.

Three tiers of frontend enum handling - use the simplest tier that fits:

| Tier | When | What to Define | Example |
|------|------|----------------|---------|
| Display only | True enum appears in grid columns, badges, read-only fields | Nothing - use EnumDTO.name from the DTO | Grid status column |
| Dropdown binding | User selects a true enum value in a form | Nothing - use EnumDTO[] from lookup endpoint | Lifecycle status dropdown |
| Programmatic comparison | Code branches on a true enum value | as const object in {entity}.enums.ts | If status is Active, show green badge |

For tenant-configurable values such as Action Types or RCA Methods, do not use this enum pattern. Load options from the owning admin module lookup endpoint and bind NamedDTO, stable Code, or the module-specific lookup DTO required by that contract.

## Tier 2: True Enum Dropdown Binding

Dropdowns for true system enums are populated from lookup endpoints that return EnumDTO[]. The selected value roundtrips to the API without transformation ([ADR-0005](../../adr/0005-enumdto-nameddto-for-ui-binding.md)).

Tenant-configurable catalogue dropdowns are different: load them from their owning admin module /lookups endpoint and bind the contract shape that module exposes, typically NamedDTO plus stable code.

### Tier 2: Dropdown Binding Example 1

```typescript
// In the feature service
getEvidenceTypeOptions(): Promise<EnumDTO[]> {
  return firstValueFrom(

  );
}
```

## Tier 3: Programmatic Comparison

When component logic branches on an enum value, define an `as const` object with string values matching the C# enum member names. Compare against `EnumDTO.name`. See [ADR-0023](../../adr/0023-as-const-enum-constants-on-web.md).

### Defining Constants

Create `{entity}.enums.ts` colocated with the feature models:

```typescript
// action.enums.ts

export const ActionStatus = {
  Active: 'Active',
  Inactive: 'Inactive',
} as const;
export type ActionStatus = (typeof ActionStatus)[keyof typeof ActionStatus];
// yields: 'Active' | 'Inactive'

export const EvidenceType = {
  Public: 'Public',
  Confidential: 'Confidential',
} as const;
export type EvidenceType = (typeof EvidenceType)[keyof typeof EvidenceType];
```

**Rules:**
- Values are **string names** matching C# enum member names (`'Active'`, not `0`)
- Compare against `EnumDTO.name` (not `EnumDTO.id`)
- No display labels — those come from `EnumDTO.name` on the DTO
- Only define constants for enums you actually compare against in code
- File lives alongside `{entity}.models.ts` in the feature folder
- Shared constants (used across features) go in `core/models/`

### Comparing

```typescript
import { ActionStatus, EvidenceType } from './action.enums';

// Conditional rendering
readonly isActive = computed(() =>
  this.dto()?.status.name === ActionStatus.Active
);

// Conditional styling
statusBadgeClass(status: EnumDTO): string {
  switch (status.name) {
    case ActionStatus.Active:
      return 'badge bg-success';
    case ActionStatus.Inactive:
      return 'badge bg-secondary';
    default:
      return '';
  }
}

// Guard logic
readonly canDelete = computed(() => {
  const action = this.dto();
  return app != null && !app.isCore && !app.isFirstParty;
});

readonly showSecretColumn = computed(() =>
  this.dto()?.evidence.some(c => c.evidenceType.name === EvidenceType.Confidential) ?? false
);
```

## What NOT to Do

```typescript
// ✗ Don't use TypeScript enum — broken with --isolatedModules, non-erasable
enum ActionStatus { Active = 'Active', Inactive = 'Inactive' }

// ✗ Don't use const enum — broken with Angular CLI's --isolatedModules
const enum ActionStatus { Active = 'Active', Inactive = 'Inactive' }

// ✗ Don't duplicate display labels — server is the source of truth
export const ActionStatusLabels = { Active: 'Enabled', Inactive: 'Disabled' };

// ✗ Don't use enum types as DTO fields — breaks dropdown binding (ADR-0005)
export type ActionStatus = 'Active' | 'Inactive';
export interface ActionDTO { status: ActionStatus; }
// Use EnumDTO instead:
export interface ActionDTO { status: EnumDTO; }

// ✗ Don't use magic strings for comparison — use named constants
if (dto.status.name === 'Active') { ... }

// ✗ Don't define constants for enums you never compare against
// If evidenceType only appears in dropdowns, skip it
```
