# List Page Pattern — NXGN Actions Web

> Generated from the lex graph. Do not edit this file as source of truth; update graph entities and re-export.

**Ref Code:** PAT-CORE-WEB-LIST-PAGE

## Purpose

AI Summary: Admin list pages use nxgn-content, nxgn-grid-page, nxgn-grid-page-title, and nxgn-server-grid bound to a server-side grid-list endpoint. Add/Edit navigation goes to routed capture pages. List pages do not open create/edit modals and do not implement client-side paging over all rows.

## Prerequisites

These packages and local helpers must be available before implementing a standalone list page. If they are missing, add them first. See [Overview - Required Packages](overview.md#required-packages) for setup instructions.

## Current Server Grid-List Standard

New admin list pages must use nxgn-server-grid with a feature-owned grid-list endpoint constant from core/grid/grid-endpoints.ts. The page shell uses nxgn-content nxgn-grid-page and nxgn-grid-page-title. The Add action navigates to /admin/<module>/new and row double-click/Edit navigate to /admin/<module>/{id}. Large lists use server-side paging, sorting, search, and filters through the grid-list endpoint.

## Lifecycle

```
Route activates (/admin/workflows)
  |
  |-- Feature route array loads the list leaf component
  |
  |-- Component renders nxgn-grid-page-title and nxgn-server-grid
  |
  |-- nxgn-server-grid POSTs to the configured grid-list endpoint
  |     |-- endpoint comes from GRID_ENDPOINTS.{feature}
  |     |-- request includes page size, sort/search state, and extraRequestFields
  |     |-- API returns GridListResponse<GridItemDTO>
  |
  |-- Grid renders server-returned rows and total count
  |
  |-- User interacts:
  |     |-- Selects rows -> selectionChanged -> selectedRows.set(...)
  |     |-- Double-clicks row -> navigate to capture page (edit)
  |     |-- Clicks Add -> navigate to capture page (new)
  |     |-- Clicks Edit -> navigate to capture page (selected row)
  |     |-- Clicks Delete -> confirm -> feature service delete command -> grid.refresh()
  |
  |-- Tenant changes or mutation completes -> clear selection and refresh server grid
```

```html
<div class="nxgn-content nxgn-grid-page p-4">
  <nxgn-grid-page-title
    [title]="i18n.workflows.list.title | translate"
    [showAdd]="!isGridDegraded()"

    [showDelete]="!isGridDegraded()"

    <div class="alert alert-danger" role="alert">

    </div>
  }

  <nxgn-server-grid
    #grid
    [endpoint]="gridEndpoint"
    [columnDefs]="columnDefs()"
    [defaultColDef]="gridDefaultColDef"
    [extraRequestFields]="gridExtraFields()"
    [pageSize]="gridPageSize"
    [paginationPageSizeSelector]="gridPageSizeSelector"
    [multiSelect]="true"
    (rowDoubleClicked)="onRowDoubleClicked($event)"
    (selectionChanged)="onSelectionChanged($event)"
  />
</div>
```

### Template Rules

| Rule | Detail |
|------|--------|
| **Content shell** | Wrap standalone admin lists in `nxgn-content nxgn-grid-page` |
| **Toolbar before grid** | `nxgn-grid-page-title` always above `nxgn-server-grid` |
| **Server grid endpoint** | Bind `[endpoint]` to a `GRID_ENDPOINTS` constant |
| **Multi-select when toolbar actions need it** | `[multiSelect]="true"` enables selection for Edit/Delete |
| **Bind selectedItems to toolbar** | Controls Edit/Delete disabled state automatically |
| **Always use translate pipe** | Titles, alerts, button labels, empty states, and status text |
| **Grid degraded state** | Disable toolbar actions when `grid()?.persistentErrorMessage()` is present |
| **Embedded exception** | Use `nxgn-data-grid` only for child collections inside capture pages |

## Component Structure

```typescript
import { ChangeDetectionStrategy, Component, computed, inject, signal, viewChild } from '@angular/core';
import { Router } from '@angular/router';
import {
  ConfirmationDialogService,
  GridPageTitleComponent,
  ServerGridComponent,
} from '@nxgn-solutions/ui';
import { TranslatePipe, TranslateService } from '@ngx-translate/core';
import { type ColDef, type RowDoubleClickedEvent } from 'ag-grid-community';

import { GRID_ENDPOINTS } from '../../../core/grid/grid-endpoints';
import {
  getSelectedServerRows,
  SERVER_GRID_DEFAULT_COL_DEF,
  SERVER_GRID_PAGE_SIZE,
  SERVER_GRID_PAGE_SIZE_SELECTOR,
  type ServerGridSelection,
  tenantScopedServerGridFields,
} from '../../../core/grid/server-grid';
import { WorkflowGridItemDTO } from './workflow.models';
import { WorkflowService } from './workflow.service';

@Component({
  selector: 'app-workflow-list',
  standalone: true,
  imports: [GridPageTitleComponent, ServerGridComponent, TranslatePipe],
  templateUrl: './workflow-list.component.html',
  changeDetection: ChangeDetectionStrategy.OnPush,
})
export class WorkflowListComponent {
  private readonly confirmationDialogService = inject(ConfirmationDialogService);
  private readonly router = inject(Router);
  private readonly translate = inject(TranslateService);
  private readonly workflowService = inject(WorkflowService);
  private readonly grid = viewChild<ServerGridComponent<WorkflowGridItemDTO>>('grid');

  readonly selectedRows = signal<WorkflowGridItemDTO[]>([]);
  readonly selectedItems = computed(() => this.selectedRows().map(row => ({ id: row.id })));
  readonly isGridDegraded = computed(() => Boolean(this.grid()?.persistentErrorMessage()));
  readonly errorMessage = signal<string | null>(null);

  readonly gridEndpoint = GRID_ENDPOINTS.workflows;
  readonly gridDefaultColDef = SERVER_GRID_DEFAULT_COL_DEF;
  readonly gridPageSize = SERVER_GRID_PAGE_SIZE;
  readonly gridPageSizeSelector = SERVER_GRID_PAGE_SIZE_SELECTOR;
  readonly gridExtraFields = tenantScopedServerGridFields(() => ({}));

  readonly columnDefs = computed<ColDef<WorkflowGridItemDTO>[]>(() => [
    { field: 'name', headerName: this.translate.instant('workflows.list.columns.name'), flex: 1.8 },
    { field: 'version', headerName: this.translate.instant('workflows.list.columns.version'), flex: 0.6 },
  ]);

  onSelectionChanged(event: ServerGridSelection<WorkflowGridItemDTO>): void {
    if (this.isGridDegraded()) {
      this.clearSelection();
      return;
    }

    this.selectedRows.set(getSelectedServerRows(event));
  }

  onRowDoubleClicked(event: RowDoubleClickedEvent<WorkflowGridItemDTO>): void {
    if (!this.isGridDegraded() && event.data) {
      void this.router.navigate(['/admin/workflows', event.data.id]);
    }
  }

  onAdd(): void {
    if (!this.isGridDegraded()) {
      void this.router.navigate(['/admin/workflows/new']);
    }
  }

  onEdit(): void {
    const selected = this.selectedRows();
    if (!this.isGridDegraded() && selected.length === 1) {
      void this.router.navigate(['/admin/workflows', selected[0].id]);
    }
  }

  async onDelete(): Promise<void> {
    const selected = this.selectedRows();
    if (this.isGridDegraded() || selected.length === 0) {
      return;
    }

    const confirmed = await this.confirmationDialogService.confirm(
      this.translate.instant('workflows.list.deleteMessage', { count: selected.length }),
      this.translate.instant('workflows.list.deleteTitle'),
      { variant: 'danger' },
    );

    if (!confirmed) {
      return;
    }

    try {
      for (const row of selected) {
        await this.workflowService.deleteDraft(row.id, { rowVersion: row.rowVersion ?? null });
      }
      this.refreshGrid();
    } catch {
      this.refreshGrid();
      this.errorMessage.set(this.translate.instant('workflows.list.deleteError'));
    }
  }

  private refreshGrid(): void {
    this.clearSelection();
    this.grid()?.refresh();
  }

  private clearSelection(): void {
    this.selectedRows.set([]);
  }
}
```

## Grid Item DTO

Grid item DTOs are flat projections — counts instead of child arrays, `EnumDTO` for classification fields. See [Feature Service — Model Rules](feature-service.md) for full conventions.

```typescript

export interface ActionGridItemDTO {
```

## Column Definitions

### EnumDTO Column Formatting

Because classification fields are `EnumDTO` (not bare strings), column definitions must extract `.name` for display and use `.name` for styling:

```typescript
// ✓ CORRECT — extract EnumDTO.name for display and styling
{
  field: 'status',
  headerName: 'Status',
  flex: 1,
  valueFormatter: (params) => params.value?.name ?? '',
  cellClass: (params) => {
    switch (params.value?.name) {
      case 'Open': return 'text-success';
      case 'Closed': return 'text-danger';
      default: return 'text-muted';
    }
  },
}

// ✗ WRONG — treats status as bare string (breaks with EnumDTO)
{
  field: 'status',
  headerName: 'Status',
  cellClass: (params) => params.value === 'Open' ? 'text-success' : 'text-danger',
}
```

### NamedDTO Column Formatting

FK reference columns use `valueGetter` to extract the display name:

```typescript
// ✓ CORRECT — extract NamedDTO.name for display
{
  headerName: 'Workflow',
  flex: 1.5,
  valueGetter: (params) => params.data?.workflow?.name ?? '',
}

// ✗ WRONG — displays raw GUID
{
  field: 'workflowId',
  headerName: 'Workflow',
  flex: 1.5,
}
```

### Common Column Patterns

```typescript
// Date column
{
  field: 'createdDate',
  headerName: 'Created',
  flex: 1,
  valueFormatter: (params) =>
    params.value ? new Date(params.value).toLocaleDateString() : '',
}

// Boolean column
{
  field: 'isOverdue',
  headerName: 'Overdue',
  flex: 0.6,
  valueFormatter: (params) => params.value ? 'Yes' : 'No',
  cellClass: (params) => params.value ? 'text-danger' : 'text-success',
}

// Count column (from flat grid item DTO)
{
  field: 'evidenceCount',
  headerName: 'Evidence',
  flex: 0.6,
}

// Truncated text column
{
  field: 'description',
  headerName: 'Description',
  flex: 2,
  valueFormatter: (params) => {
    const val = params.value;
    return val?.length > 60 ? val.substring(0, 60) + '...' : (val ?? '');
  },
}
```

## Key Rules

### Selection

| Rule | Detail |
|------|--------|
| **Track selection as `signal<{ id: string }[]>`** | Consistent shape for toolbar binding |
| **Use `selectionChanged` event** | Emits the full selected row array |
| **Map rows to `{ id }` objects** | `rows.map(r => ({ id: r.id }))` |
| **Edit requires exactly 1** | Check `selected.length === 1` before navigating |
| **Delete requires at least 1** | Check `selected.length === 0` and return early |

```typescript
// ✓ CORRECT — map to { id } for toolbar binding
onSelectionChanged(rows: ActionGridItemDTO[]): void {
  this.selectedItems.set(rows.map(r => ({ id: r.id })));
}

// ✗ WRONG — passing full DTOs to toolbar (leaks domain details)
onSelectionChanged(rows: ActionGridItemDTO[]): void {
  this.selectedItems.set(rows);
}
```

### Navigation

| Rule | Detail |
|------|--------|
| **Double-click → edit** | Navigate to capture page with entity ID |
| **Add → `/feature/new`** | New entity route |
| **Edit → `/feature/{id}`** | Single selected entity |
| **Always child routes, never modals** | Consistent navigation pattern |
| **Absolute routes for standalone lists** | `/admin/actions/{id}` |

```typescript

  }
}

// ✗ WRONG — opening a modal for edit
```

### Delete

| Rule | Detail |
|------|--------|
| **Always confirm** | `ConfirmationDialogService.confirmDelete()` before API call |
| **Translated messages** | Confirmation title and message through `TranslateService` |
| **Reload after delete** | Call `load()` to refresh the grid from the server |
| **Toaster for result** | Success → `toastr.success()`, error → `toastr.error()` |
| **Aggregate roots use bulk delete** | `POST /delete` with `{ entityKeys: string[] }` |
| **Simple entities use single delete** | `DELETE /{id}` |

```typescript
// ✓ CORRECT — full delete flow: confirm → API → toast → reload
async onDelete(): Promise<void> {
  const selected = this.selectedItems();
  if (selected.length === 0) return;

  const confirmed = await this.confirmService.confirmDelete(
    await firstValueFrom(this.translate.get('actions.list.deleteTitle')),
    await firstValueFrom(
      this.translate.get('actions.list.deleteMessage', { count: selected.length }),
    ),
  );
  if (!confirmed) return;

  try {
    await this.actionService.delete({ entityKeys: selected.map(s => s.id) });
    this.toastr.success(
      await firstValueFrom(this.translate.get('actions.list.deleteSuccess', { count: selected.length })),
    );
    await this.load();
  } catch {
    this.toastr.error(
      await firstValueFrom(this.translate.get('actions.list.deleteError')),
    );
  }
}

// ✗ WRONG — no confirmation dialog
async onDelete(): Promise<void> {
  await this.actionService.delete({ entityKeys: this.selectedItems().map(s => s.id) });
  await this.load();
}

// ✗ WRONG — browser confirm() instead of ConfirmationDialogService
async onDelete(): Promise<void> {
  if (!confirm('Delete?')) return;  // ← use ConfirmationDialogService
}
```

### Data Loading

| Rule | Detail |
|------|--------|
| **Service method: `getGridList(page, pageSize, search?, ...filters?)`** | See [Feature Service](feature-service.md) |
| **Returns `GridListResponse<T>`** | `{ items: T[], totalCount: number, page: number, pageSize: number }` |
| **Grid list uses POST to `/grid-list`** | POST with filter payload, not GET with query params |
| **Set loading before/after** | `loading.set(true)` in try, `loading.set(false)` in finally |
| **Reload after any mutation** | Delete, domain commands — always call `load()` |

### Component Class

| Rule | Detail |
|------|--------|
| **Standalone component** | `standalone: true` in `@Component` metadata |
| **OnPush change detection** | `changeDetection: ChangeDetectionStrategy.OnPush` |
| **`inject()` for DI** | No constructor parameters |
| **Signals for all state** | `signal()` for `dataItems`, `loading`, `totalCount`, `selectedItems` ([ADR-0006](../../adr/0006-signal-based-state-over-behaviorsubject.md)) |
| **`async/await` for API calls** | Components never handle Observables directly |
| **Feature-colocated service** | `inject(ActionService)`, not a global service ([ADR-0007](../../adr/0007-feature-colocated-services-on-web.md)) |

## Filtering

Some list pages support filtering via query parameters (e.g., actions filtered by workflow, evidence filtered by action ID). The filter value comes from `ActivatedRoute.queryParams`.

```typescript
// action-list.component.ts (excerpt)
private readonly route = inject(ActivatedRoute);

workflowFilter = signal<string | null>(null);

async ngOnInit(): Promise<void> {
  const params = this.route.snapshot.queryParams;
  if (params['workflow']) {
    this.workflowFilter.set(params['workflow']);
  }
  await this.load();
}

private async load(): Promise<void> {
  this.loading.set(true);
  try {
    const result = await this.actionService.getGridList(
      1, 100, undefined, this.workflowFilter() ?? undefined,
    );
    this.dataItems.set(result.items);
    this.totalCount.set(result.totalCount);
  } finally {
    this.loading.set(false);
  }
}

onClearFilter(): void {
  this.workflowFilter.set(null);
  this.router.navigate([], { queryParams: {} });
  this.load();
}
```

The template shows a filter banner when a filter is active:

```html
@if (workflowFilter()) {
```

```html
    <button type="button" class="btn btn-sm btn-outline-secondary" (click)="onClearFilter()">
      {{ 'common.clearFilter' | translate }}
    </button>
  </div>
}
```

## Pagination

Grid lists support server-side pagination. The default is page 1, pageSize 25. Page state is tracked via signals and synced to query params for back-navigation preservation.

### Paginated List Component

```typescript
// State
page = signal(1);
pageSize = signal(25);

// Derived
totalPages = computed(() => Math.ceil(this.totalCount() / this.pageSize()));

// Data loading passes current page/pageSize
private async load(): Promise<void> {
  this.loading.set(true);
  try {
    const result = await this.actionService.getGridList(
      this.page(), this.pageSize(), this.searchTerm(),
    );
    this.dataItems.set(result.items);
    this.totalCount.set(result.totalCount);
  } finally {
    this.loading.set(false);
  }
}

// Page change handler — update signal and reload
onPageChange(newPage: number): void {
  this.page.set(newPage);
  this.load();
}

onPageSizeChange(newSize: number): void {
  this.pageSize.set(newSize);
  this.page.set(1);  // Reset to first page
  this.load();
}
```

### Pagination Template

```html
@if (!loading() && totalCount() > pageSize()) {
  <div class="d-flex justify-content-between align-items-center mt-3">
    <span class="text-muted">
      {{ 'common.showingRange' | translate:{
        from: (page() - 1) * pageSize() + 1,
        to: page() * pageSize() > totalCount() ? totalCount() : page() * pageSize(),
        total: totalCount()
      } }}
    </span>
    <nav>
      <ul class="pagination pagination-sm mb-0">
        <li class="page-item" [class.disabled]="page() === 1">
          <button class="page-link" (click)="onPageChange(page() - 1)">&laquo;</button>
        </li>
        @for (p of [].constructor(totalPages()); track $index) {
          <li class="page-item" [class.active]="$index + 1 === page()">
            <button class="page-link" (click)="onPageChange($index + 1)">{{ $index + 1 }}</button>
          </li>
        }
        <li class="page-item" [class.disabled]="page() === totalPages()">
          <button class="page-link" (click)="onPageChange(page() + 1)">&raquo;</button>
        </li>
      </ul>
    </nav>
  </div>
}
```

### When to Paginate

| Data volume | Pattern |
|-------------|---------|
| < 100 rows typical | Load all with `page=1, pageSize=100` — no pagination UI |
| 100+ rows typical | Full pagination with page/pageSize signals |
| Audit logs, history | Always paginate — unbounded data |

Most admin entity lists (actions, workflows, compliance profiles) start with the simple `page=1, pageSize=100` approach. Add pagination when the entity count is expected to exceed 100 rows.

## Departures from Capstone

| Aspect | Capstone | Actions | Why |
|--------|----------|---------|-----|
| **Service location** | Centralized `GridPageService` plus feature data services in `core/services/` | Feature-colocated `{entity}.service.ts` | [ADR-0007](../../adr/0007-feature-colocated-services-on-web.md) - mirrors API vertical slices |
| **DI style** | Constructor injection | `inject()` function | Modern Angular standalone convention |
| **State management** | Plain properties (`isLoaded`, `dataItems`, `selectedItems`) | Signals (`signal()`, `computed()`) plus server-grid component state | [ADR-0006](../../adr/0006-signal-based-state-over-behaviorsubject.md) - reactive state |
| **Change detection** | Default zone-based | `OnPush` with signal-driven state | Signal-based state enables predictable rendering |
| **Data loading** | Component/service manually calls `GetGridList` and binds local arrays | `nxgn-server-grid` POSTs to a `/grid-list` endpoint from `GRID_ENDPOINTS` | Server-side paging/search/sort remains inside the grid contract |
| **Delete confirmation** | `window.confirm()` with translated string | `ConfirmationDialogService.confirm()` or `confirmDelete()` | Styled modal consistent with app design |
| **Delete error handling** | Partial success via response arrays | Full success/failure; refresh grid after success or error | Actions API commands are transactional |
| **Selection tracking** | `@ViewChild` plus imperative `getSelectedNodes()` | `(selectionChanged)` event -> `getSelectedServerRows()` -> `signal<DTO[]>()` | Declarative signal flow avoids leaking grid internals |
| **Standalone grid component** | `NxgnGridComponent` or local client-side wrappers | `ServerGridComponent` / `nxgn-server-grid` | Shared server-side grid contract |
| **Embedded child grid component** | Same grid primitive as list pages | `DataGridComponent` / `nxgn-data-grid` only inside capture pages | Child rows are local aggregate state until parent Save |
| **Toolbar component** | `EntityGridPageTitleComponent` with legacy projection | `GridPageTitleComponent` with named projection | Shared UI library plus modern control flow |
| **Grid resize** | Manual window resize handling | Handled internally by the grid component | Shared grid component owns layout behavior |
| **Column translation** | `await lastValueFrom(translate.get('key'))` in `configureColumns()` | Translation keys come from the shell contract and refresh through signals where needed | Keeps Actions translation ownership centralized |
| **Observable handling** | `lastValueFrom()` | `firstValueFrom()` or signal interop | HTTP emits once; signal interop handles reactive shell state |
| **Add/Edit navigation** | `Router.navigate([captureRoute], { state: captureCriteria })` with `IEntityCaptureCriteria` | `Router.navigate(['/admin/feature', id])`; route param determines mode | Deep-linkable routes and simpler state |

## Rules

### MUST

- Admin list pages must use nxgn-server-grid with a server-side grid-list endpoint unless the page is explicitly an embedded child picker or lookup component.
- List page Add/Edit actions must navigate to routed capture pages, not open create/edit modals.

### MUST NOT

- Do not implement large admin lists by loading all rows client-side and paging/filtering in the browser.
