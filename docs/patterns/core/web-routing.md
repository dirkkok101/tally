# Routing Pattern — NXGN Actions Web

> Generated from the lex graph. Do not edit this file as source of truth; update graph entities and re-export.

**Ref Code:** PAT-CORE-WEB-ROUTING

## Purpose

**AI Summary**: Admin feature route groups are lazy-loaded with `loadChildren` returning standalone `Routes` arrays, while leaf routes use `loadComponent` for standalone components. Route parameters bind to component `input()` signals via `withComponentInputBinding()`. The app route tree owns shell/auth boundaries; feature route files own local list/capture paths, permission guards, and child-route arrays. NgModule routing remains forbidden.

## Prerequisites

- `@angular/router` — `provideRouter`, `withComponentInputBinding`, `Routes`
- `angular-auth-oidc-client` — OIDC authentication for admin guard
- Reference [Overview — Required Packages](overview.md#required-packages) for full list

## Route Definition Rules

### MUST

1. Lazy-load feature route arrays from the app route tree with `loadChildren` when a feature owns a list/capture route group.
2. Export feature route arrays as `Routes` from `{feature}.routes.ts`; do not introduce Angular NgModules.
3. Use `loadComponent` on leaf routes that render standalone components.
4. Separate public/auth routes from protected application routes.
5. Put broad authentication and route-authorisation guards on parent routes; put feature permission guards on feature route entries.
6. Use the three-route pattern for CRUD entities inside the feature route array: list at `''`, create at `new`, and edit at `:id`.
7. Share the same capture component for `new` and `:id` routes.
8. Define child route arrays once, applied to both `new` and `:id` when an aggregate has child capture routes.

### MUST NOT

1. Use NgModule-based routing. `loadChildren` is allowed only when it returns a `Routes` array from a feature route file.
2. Put standalone list/capture components directly in the app-level route tree when the feature already has its own route array.
3. Use modals for list -> capture navigation - always routed pages ([ADR-0015](../../adr/0015-child-routes-over-modals-for-entity-capture.md), see [Embedded List - Navigation Rules](embedded-list.md#navigation-rules)).
4. Define route resolvers - data loading happens in components via `effect()` or lifecycle hooks.
5. Use `ActivatedRoute.paramMap` or `snapshot.paramMap` for route params that can be bound via `input()` - prefer `withComponentInputBinding()`.


## Route Definition Pattern

### App route tree

The app route tree owns shell layout, broad authentication, route authorisation, and the lazy boundaries for admin feature route arrays. Each feature route file exports `Routes`; this is not NgModule routing.

```typescript

  {
    path: 'action-types',
    loadChildren: () => import('./modules/admin/action-types/action-types.routes')
      .then(m => m.actionTypesRoutes),
  },
  {
    path: 'rca-methods',
    loadChildren: () => import('./modules/admin/rca-methods/rca-methods.routes')
      .then(m => m.rcaMethodsRoutes),
  },
  {
    path: 'workflows',
    loadChildren: () => import('./modules/admin/workflows/workflows.routes')
      .then(m => m.workflowsRoutes),
  },
];

export const routes: Routes = [
  {
    path: '',
    component: AppShellLayoutComponent,
    canActivate: [authGuard],
    children: [
      {
        path: '',
        canActivateChild: [authRouteGuard],
        children: [
          {
            path: 'admin',
            children: adminRoutes,
          },
        ],
      },
    ],
```
```typescript
  },
];
```

## Route Parameter Binding

`withComponentInputBinding()` automatically maps route parameters to component `input()` signals with matching names:

```typescript
// Route: /admin/actions/:id
// Component:
id = input<string>();  // Bound from `:id` — undefined on /new, GUID on /:id

// Route: /admin/actions/:id/evidence/:evidenceRef
// Child component:
evidenceRef = input<string>();  // Bound from `:evidenceRef`
```

### New vs Edit Mode Detection

The capture component determines mode from the route parameter:

```typescript
const GUID_REGEX = /^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i;

id = input<string>();

isEditMode = computed(() => {
  const idVal = this.id();
  return !!idVal && GUID_REGEX.test(idVal);
});
```

- `/workflows/new` → `id()` is `undefined` → create mode
- `/workflows/{guid}` → `id()` is a valid GUID → edit mode

### ✓ Correct — input() with withComponentInputBinding()

```typescript
id = input<string>();

constructor() {
  effect(() => {
    const idVal = this.id();
    if (idVal && GUID_REGEX.test(idVal)) {
      this.loadEntity(idVal);
    }
  });
}
```

### ✗ Wrong — manual ActivatedRoute extraction

```typescript
// Don't do this when withComponentInputBinding() is configured
private route = inject(ActivatedRoute);

ngOnInit(): void {
  const id = this.route.snapshot.paramMap.get('id');
  if (id) this.loadEntity(id);
}
```

**Exception**: Child route components that need the parent's route param use `this.route.parent?.snapshot.params['id']` because the parent param is not in the child's input scope.

## Auth Guard

The admin auth guard uses a functional `CanActivateFn` with OIDC:

```typescript
// core/guards/admin-auth.guard.ts
import { inject } from '@angular/core';
import { CanActivateFn, Router } from '@angular/router';
import { OidcSecurityService } from 'angular-auth-oidc-client';
import { firstValueFrom } from 'rxjs';

export const adminAuthGuard: CanActivateFn = async () => {
  const oidcService = inject(OidcSecurityService);
  const router = inject(Router);

  try {
    const { isAuthenticated } = await firstValueFrom(oidcService.isAuthenticated$);
    if (isAuthenticated) return true;

    // Trigger OIDC login flow — redirects to /connect/authorize
    oidcService.authorize();
    return false;
  } catch {
    // OIDC discovery or configuration error
    return router.createUrlTree(['/login'], {
      queryParams: { error: 'oidc_unavailable' },
    });
  }
};
```

### Guard rules

| Rule | Detail |
|------|--------|
| Guard placement | On the `/admin` parent route only — children inherit |
| Guard type | Functional `CanActivateFn`, never class-based |
| Auth failure | Trigger OIDC authorize flow (redirect to IdP) |
| Config error | Return `UrlTree` redirect to login with error parameter |
| Public routes | Never guarded: OIDC callback |

## Programmatic Navigation

### List → capture

```typescript
// Add: navigate to /new
onCreateAction(): void {
  this.router.navigate(['/admin/actions/new']);
}

// Edit: navigate to /:id (single-select or double-click)
onEdit(): void {
  const selected = this.selectedItems();
  if (selected.length === 1) {
    this.router.navigate(['/admin/actions', selected[0].id]);
  }

    this.router.navigate(['/admin/actions', event.data.id]);
  }
}
```

### Capture → list (cancel/save)

```typescript
// Cancel navigates back to list

  this.router.navigate(['/admin/workflows']);

async onSave(): Promise<void> {
  const result = await this.workflowService.save(request);
  if (this.isEditMode()) {
    await this.loadWorkflow(this.id()!);  // Reload in place

    this.router.navigate(['/admin/workflows', result.id]);  // Redirect to edit
```

### Parent → child route (embedded list actions)

Embedded list components inside a capture page navigate to child routes using **relative paths**. This keeps the navigation independent of the parent's route structure:

```typescript

private readonly route = inject(ActivatedRoute);

onAdd(): void {
  this.router.navigate(['evidence', 'new'], { relativeTo: this.route });
```

### Child route → parent

Child components navigate back to the parent capture using absolute paths:

```typescript
// In child route component (e.g., ActionEvidenceCaptureComponent)
private navigateBack(): void {
  const id = this.route.parent?.snapshot.params['id'];
  this.router.navigate(['/admin/actions', id ?? 'new']);
}
```

### Navigation direction rules

| Direction | Style | Example |
|-----------|-------|---------|
| List → capture | Absolute | `['/admin/actions', id]` |
| Capture → list | Absolute | `['/admin/actions']` |
| Parent → child route | Relative | `['evidence', 'new'], { relativeTo: this.route }` |
| Child route → parent | Absolute | `['/admin/actions', id]` |

### ✓ Correct — relative for parent → child

```typescript
this.router.navigate(['evidence', evidenceId], { relativeTo: this.route });
```

### ✗ Wrong — relative for navigating back up

```typescript
// Don't use relative parent traversal — fragile with nested child routes
this.router.navigate(['..'], { relativeTo: this.route });
```

## Child Route Data Flow

Child routes share aggregate data with the parent via a component-level `CaptureState` service. See [Capture State](capture-state.md) for full details.

```

  └── <router-outlet> → Child Capture (reads/writes CaptureState.children)
```

## Query Parameters

Use query parameters for optional filters that don't define a unique resource:

```typescript
// Reading: /admin/roles?action=abc123
private readonly route = inject(ActivatedRoute);

ngOnInit(): void {
  const action = this.route.snapshot.queryParamMap.get('action');
  if (action) {
    this.actionFilter.set(action);
  }
}

// Writing: navigate with query params
this.router.navigate(['/admin/roles'], {
  queryParams: { action: appId },
});
```

Query params are appropriate for filter state on list pages. Entity identity always uses path params (`:id`).

## Departures from Capstone

| Concern | Capstone | Actions | Why |
|---------|----------|----------|-----|
| Route structure | Flat routes at app level | Nested under `/admin` shell | Shell provides shared layout (sidebar, nav, logout) |
| Route param binding | `@Input()` + `route.snapshot.data` fallback | `input()` via `withComponentInputBinding()` | Signal-based inputs (ADR-0006), automatic binding |
| Entity passing | `history.state` with `IEntityCaptureCriteria` | Route param `:id`, load from API | Deep-linkable URLs, no stale state on refresh |
| Navigation services | `GridPageService` / `CapturePageService` | Direct `router.navigate()` in components | Feature service handles HTTP ([ADR-0007](../../adr/0007-feature-colocated-services-on-web.md)), navigation is component responsibility |
| Child routes | No child routes (flat structure) | Nested child routes for aggregate children | Enables capture state sharing and child entity CRUD without modals |
| Route data metadata | `data: { title, captureRoute, apiRoute }` | None | Components know their own feature context; no generic grid/capture services |
| Route guards | Class-based `AuthGuard` on every route | Functional `CanActivateFn` on parent only | Modern Angular pattern, children inherit guard |

## Rules

### MUST

- Feature route groups must be lazy-loaded with loadChildren returning a standalone Routes array; leaf routes use loadComponent for standalone components.

### MUST NOT

- Do not use NgModule-based routing; loadChildren is allowed only for standalone Routes arrays exported from feature route files.
