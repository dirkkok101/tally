## Recipe

### Acceptance Checks

- Given a LEDGER actuals snapshot whose items carry FrozenAncestryIds, when BudgetContractMapper.TryMapActualMembers runs, then each produced BudgetActualMember carries that same ancestry list in the same order rather than an empty list.
- Given a LEDGER actuals item with no assigned Spend Category, when the member is mapped, then its AncestryIds list is empty and its CategoryId is null.
- Given a Budget Actual assigned to a Spend Category whose ancestor is archived and absent from the default category listing, when the position query assembles known Spend Category evidence, then that ancestor identifier is fetched and present so ancestry validation does not fail.
- Given a Budget Position request, when the required Spend Category identifier set is assembled, then it contains every plan entry category, every member category, and every ancestry element.

### Failure Criteria

- Do NOT reach into LEDGER private storage or recompute ancestry inside BUDGET — consume ancestry only from the public actuals snapshot, per DD-BUDGET-LEDGER-PUBLIC-COMPOSITION.
- Do NOT issue one LEDGER actuals query per Category Budget Entry using the categoryScope subtree filter — rejected alternative B in DD-BUDGET-CATEGORY-ENVELOPE-RESOLUTION, because nested entries return overlapping membership and it breaks the single-complete-snapshot rule.
- Do NOT resolve, bucket, or aggregate anything in this task — TASK-BUDGET-ENVELOPE-RESOLUTION owns resolution.

### Expected Outputs

- Mapper that carries FrozenAncestryIds into BudgetActualMember.AncestryIds
- Required Spend Category identifier set extended with every ancestry element

### Constraints

- One complete compatible actuals snapshot per position; no additional LEDGER actuals query is introduced.
- CancellationToken flows through every added async call.

### Notes

- The discard is at BudgetContractMapper.TryMapActualMembers where BudgetActualMember is constructed from item.Ordinal, item.TransactionId, item.EffectiveDate, item.CategoryId and the parsed contribution only; item.FrozenAncestryIds is currently dropped.
- The required identifier set is built in GetBudgetPositionQuery from plan entries and member.CategoryId; ancestry elements must be added before the per-identifier category fetch loop runs.
