## Recipe

### Acceptance Checks

- Given a categorized member whose ancestry is empty, does not end with its assigned Spend Category identifier, repeats an identifier, or names an identifier absent from known Spend Category evidence, when the position is calculated, then BudgetErrors.Integrity is returned with an amount-free integrity reason token and no position row or totals.
- Given an uncategorized member whose ancestry list is non-empty, when the position is calculated, then BudgetErrors.Integrity is returned with no partial totals.
- Given descendant Budget Actuals whose absorbed sum exceeds Int64 range, when the position is calculated, then BudgetErrors.Integrity is returned, no position row or totals are produced, and no amount appears in the failure message.
- Given a parent Category Budget Entry and descendant Budget Actuals whose signed sum is negative because refunds exceed spend, when the position is returned, then the exact negative value is preserved in both the descendant actual and the row actual, the row stays in the Budgeted bucket, and the membership reconciliation assertion still holds.
- Given an archived ancestor Spend Category carrying a Category Budget Entry and an active descendant carrying none, when the position is calculated, then the archived ancestor row absorbs the descendant Budget Actuals exactly once and reports its archived lifecycle.

### Failure Criteria

- Do NOT clamp, zero, or reclassify a negative Budget Actual — refund-heavy negatives stay signed, per DD-BUDGET-CATEGORY-ENVELOPE-RESOLUTION.
- Do NOT skip an archived ancestor during resolution — Spend Category lifecycle never changes bucket assignment, per DD-BUDGET-CATEGORY-ENVELOPE-RESOLUTION.
- Do NOT return a partial position, partial totals, or a best-effort row when integrity fails — per DD-BUDGET-EXACT-POSITION-CALCULATION overflow yields a stable integrity failure with no partial result.
- Do NOT include any monetary amount in an integrity failure message or reason token — amount-free diagnostics only.

### Expected Outputs

- Ancestry validation mirroring the LEDGER ActualsCalculator invariant
- Checked Int64 overflow handling across the absorbed-sum path
- Archived-ancestor and refund-sign behavior proven by test

### Constraints

- Integrity failures use the existing BudgetErrors.Integrity code and the existing amount-free reason-token mechanism.
- No new error code is introduced for ancestry violations.

### Notes

- The calculator already carries an amount-free integrity reason token mechanism via Exception.Data; reuse it rather than adding a parallel channel.
- The LEDGER ActualsCalculator applies the same ancestry invariant to snapshot rows: non-empty with the final element equal to the category identifier when categorized, empty when uncategorized, distinct elements.
