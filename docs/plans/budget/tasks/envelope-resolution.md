## Recipe

### Acceptance Checks

- Given a Category Budget Entry on a parent Spend Category and Budget Actuals on that parent plus descendants one and two levels below carrying no entry, when the position is calculated, then all of them appear exactly once in the parent Budgeted position, its direct actual equals only the parent-assigned Budget Actual, its descendant actual equals the sum of the two descendants, and its absorbed identifier list names both descendants in ascending ordinal order.
- Given Category Budget Entries on both a parent Spend Category and its descendant, when the position is calculated, then a Budget Actual at or below the descendant appears exactly once in the descendant position and is excluded from the parent position.
- Given a Category Budget Entry with Planned Spend equal to zero on a descendant whose ancestor has Planned Spend greater than zero, when the position is calculated, then Budget Actuals at or below that descendant appear exactly once in the descendant Zero Budget Position and the funded ancestor Remaining value is unreduced by them.
- Given a Budget Actual whose frozen ancestry carries no Category Budget Entry at any element, when the position is calculated, then it appears exactly once as Unbudgeted Spend keyed by its exact assigned Spend Category identifier, with direct actual equal to the row actual, descendant actual exactly zero, and an empty absorbed identifier list.
- Given arbitrary Spend Category trees, arbitrary Category Budget Entry placements including zero amounts, and arbitrary Budget Actual assignments, when each position is calculated, then every row actual equals its direct actual plus its descendant actual and the sum of all row actuals plus Uncategorized Spend equals the membership total.
- Given a Budget Plan Revision whose Spend Categories are all root nodes, when the position is calculated, then every bucket, ordering, value, and total equals the exact-identity result for the same inputs and every descendant actual is exactly zero.

### Failure Criteria

- Do NOT freeze ancestry at classification time or persist any historical ancestry in BUDGET — rejected alternative A in DD-BUDGET-CATEGORY-ENVELOPE-RESOLUTION, because it needs a LEDGER storage change and contradicts OQ-BUDGET-8 and A4.
- Do NOT add DescendantActualMinorUnits on top of ActualMinorUnits — the partition composes the row total exactly, per DD-BUDGET-CATEGORY-ENVELOPE-RESOLUTION.
- Do NOT let an Unbudgeted Spend row absorb descendants — only rows produced by a Category Budget Entry absorb, per DD-BUDGET-CATEGORY-ENVELOPE-RESOLUTION.
- Do NOT persist any position, actual, cursor, or report state — per DD-BUDGET-EXACT-POSITION-CALCULATION the calculator stays pure.
- Do NOT weaken or remove the existing assertion that bucket actual subtotals reconcile to the membership total — it is the exactly-once proof, per DD-BUDGET-EXACT-POSITION-CALCULATION.
- Do NOT use unchecked arithmetic for any new sum — overflow returns the stable integrity failure with no partial result.

### Expected Outputs

- Nearest-ancestor envelope resolution in the pure calculator
- Per-row direct and descendant partition with absorbed identifier list
- Ancestry validation returning the stable integrity failure

### Constraints

- The calculator performs no I/O, no storage access, and no LEDGER call.
- Ancestry is scanned from the final index toward index zero; the first element carrying a Category Budget Entry wins.
- Int64 checked addition, subtraction, and magnitude operations for every amount.
- Resolution replaces the existing exact-category key lookup inside the plan-entry loop; the surrounding exhaustive-assignment structure, ordering, and reconciliation assertion stay unchanged.
