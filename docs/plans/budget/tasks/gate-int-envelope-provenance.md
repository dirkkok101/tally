## Recipe

### Acceptance Checks

- Given Budget Actuals across a depth-three Spend Category tree with Category Budget Entries on the root and one descendant, when budget.insights.evidence.get is invoked through the published binary, then each member reports its frozen ancestry root-first with its assigned Spend Category last and reports the effective Spend Category identifier that governed it.
- Given a member resolving to Unbudgeted Spend or Uncategorized Spend, when the INSIGHTS read projection is inspected, then its effective Spend Category identifier is null rather than an invented ancestor.
- Given a Budget Actual on a descendant under a funded parent, when the descendant is reparented under a different funded Spend Category through ledger.category.reparent and the position is requested again for the same Budget Period and revision, then the Budget Actual is attributed to the new funded ancestor, the cited LEDGER snapshot identifier differs from the first read, and the bound revision identifier and status are unchanged.
- Given the complete existing position test suite, when it is run after resolution lands, then all 111 tests pass with no test modified to accommodate the new behavior.

### Failure Criteria

- Do NOT modify an existing position test to make it pass under the new rule — unchanged flat-taxonomy behavior is the regression proof, per DD-BUDGET-CATEGORY-ENVELOPE-RESOLUTION.
- Do NOT assert that a historical position is immutable across a reparent — determinism holds within one cited snapshot, not across time, per DD-BUDGET-CATEGORY-ENVELOPE-RESOLUTION and A4.
- Do NOT exercise the behavior through in-process calculator calls only — this gate proves the published operation contract.

### Expected Outputs

- Contract-level proof of per-member envelope provenance
- End-to-end proof that a reparent re-lenses a later position under a new snapshot
- Green full existing position suite

### Constraints

- Tests drive the published Native AOT binary through TALLY_PUBLISHED_BINARY, matching the existing BUDGET contract-test harness.
- TALLY_DATA_ROOT points at a temporary owner-only directory per test.
