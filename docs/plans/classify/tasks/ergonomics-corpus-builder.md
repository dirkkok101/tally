## Recipe

### Acceptance Checks

- The command requires actor, idempotency key, explicit absolute destination, fresh complete projection, and 1 through 10000 unique explicit labels; it records only a canonical request hash and aggregate terminal result in the existing operation_idempotency table.
- Owner UID, 0700 parent, containment, no symlink, regular-file identity, link count, destination non-overwrite, and byte/row limits are validated before publication.
- A same-directory recognized temporary is opened at 0600 before bytes, completely written and flushed, validated by PrivateCorpusReader, atomically renamed, and followed by parent metadata flush before terminal success.
- Success returns build ID, projection/lifecycle fingerprints, label/row/byte counts, corpus fingerprint, terminal state, and replay flag; it excludes destination and all financial payload.
- Interruptions before rename publish no destination; replay after rename succeeds only for the exact destination fingerprint; a different existing file is never replaced or removed.

### Failure Criteria

- Do not write live Ledger or CLASSIFY financial state, stdout JSONL, a tracked fixture, a path-bearing receipt, or a second corpus dialect.
- Do not follow symlinks, accept group/world permissions, overwrite different content, delete an unknown file, or commit idempotency success before durable publication.

### Expected Outputs

- PrivateCorpusWriter, BuildPrivateClassificationCorpusCommand, and aggregate contract mapper

### Constraints

- Linux owner-only filesystem semantics are mandatory; tests use mktemp disposable roots and synthetic data.

### Notes

- The existing operation_idempotency terminal_result stores the aggregate path-free terminal envelope and request fingerprint; this task performs no ClassifySchema migration.
