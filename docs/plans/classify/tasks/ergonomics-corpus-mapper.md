## Recipe

### Acceptance Checks

- Each unique owner label resolves to exactly one fresh eligible classification_v1 row and yields one existing PrivateCorpusRow with projection, category, allocation, normalization, transfer/refund, and lifecycle fingerprints copied from public Ledger truth.
- Expected no_suggestion requires no category; expected suggestion requires one active expected category; every other outcome/category tuple is rejected.
- Missing, duplicate, ineligible, stale, expired, incompatible, archived-category, and over-limit inputs return typed failures before any corpus row is published.
- ValidateClassificationRuleCommand uses the mapper and retains byte-identical aggregate validation receipts and deterministic hashes for existing fixtures.

### Failure Criteria

- Do not derive an expected label from an allocation, description, rule result, account, amount, or prior feedback.
- Do not persist rows, descriptions, amounts, transaction IDs, normalized tokens, or private paths.

### Expected Outputs

- ClassificationProjectionCorpusMapper shared by validation and corpus construction

### Constraints

- The mapper is concrete and pure; no new interface or corpus schema version is introduced.
