## Recipe

### Acceptance Checks

- Canary scans cover stdout where private owner-visible unresolved data is permitted separately from stderr, logs, classify.db, cursor bytes, idempotency receipts, crash artifacts, generated docs, and tracked files where it is forbidden.
- Symlink, hard-link, wrong owner/mode, outside-root, existing destination, oversized corpus, interruption before/after rename, cleanup replay, invalid cursor, stale Ledger, and typed expected/unexpected failures leave zero unauthorized writes or deletions.
- Query failures leave classify.db byte/hash state and Ledger allocation/revision state unchanged; corpus build changes only the exact authorized private destination after complete success.
- No network socket, cloud/model client, background worker, reflection serialization, raw request logging, private path, description, amount, normalized token, transaction ID, or account ID enters diagnostics.

### Failure Criteria

- Do not weaken an existing security test, skip linux-x64 owner checks, sanitize assertions by deleting the canary, or treat zero discovered tests as success.
- Do not read or mutate the live TALLY_DATA_ROOT; every mutation probe uses a disposable 0700 root.

- Gate output is aggregate-only and identifies failed case names without financial values.
