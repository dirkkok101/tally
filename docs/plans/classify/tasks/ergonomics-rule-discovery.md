## Recipe

### Acceptance Checks

- rule.list ANDs logical-rule, lifecycle, category, and active-membership filters; orders by createdAt then ruleVersionId; and freezes the first-page high-water key so concurrent appends do not enter the traversal.
- Every rule item contains the exact DM-CLASSIFY-RULE-DISCOVERY fields and only canonical predicates from the released closed rule grammar.
- rule-set.active.get returns the current RuleSetVersion, broadApplyAllowed, activation/validation/gate receipt identities and fingerprints, normalization/epoch/lifecycle timestamps, ordered rule-version IDs, and current category ID/display/lifecycle tuples.
- No active set returns typed not-found; invalid cursor or impossible lifecycle/membership returns a typed error with null result and zero writes.

### Failure Criteria

- Do not change classify.status, expose owner reason prose or corpus metadata, accept caller authority, or synthesize an empty active set.
- Do not use OFFSET, mutable priority, rule inference, description search, or unbounded history.

### Expected Outputs

- ClassificationRuleDiscoveryStore, ListClassificationRulesQuery, GetActiveClassificationRuleSetQuery, and rule-discovery mapper

### Constraints

- All lifecycle and membership values derive from append-only durable authority and current Ledger category lifecycle.
