## Recipe

### Acceptance Checks

- The group key is normalizationVersion, normalizedDescription, accountId, and amountDirection using ordinal equality; counts and signed/absolute minor-unit totals use checked arithmetic.
- Ordering is count descending, then normalizedDescription, accountId, and direction ordinal; topN accepts 1 through 500 and identical inputs yield identical group fingerprints.
- The pure result exposes owner-visible normalized description and aggregates but contains no transaction IDs, source paths, rule proposal, activation, feedback, or durable artifact instruction.
- Overflow, over-limit, empty normalization version, invalid direction, and impossible row accounting return typed failures with no partial groups.

### Failure Criteria

- Do not add fuzzy clustering, merchant inference, regex, token persistence, priority, rule creation, or model scoring.
- Do not log group descriptions, amounts, account IDs, or input rows from the policy.

### Expected Outputs

- UnresolvedPatternGroupingPolicy and canonical group fingerprint vectors

### Constraints

- The policy is pure, deterministic, bounded, and independent of storage or Ledger access.
