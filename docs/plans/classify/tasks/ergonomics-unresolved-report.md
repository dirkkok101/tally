## Recipe

### Acceptance Checks

- The query requires one completed retained evaluation and topN 1 through 500, then loads only no_suggestion transaction identities and joins every identity exactly once to a fresh compatible evaluation-purpose classification_v1 projection.
- Result metadata accounts for eligible no-suggestions, fresh matches, total groups, returned groups, and evaluation/projection/category/rule-set/normalization fingerprints before exposing ordered groups.
- Missing/expired/abandoned evaluation, retention gap, unmatched/duplicate fresh row, stale generation, incompatible projection, amount overflow, archived lifecycle evidence, or accounting mismatch returns a typed error, null result, and zero writes.
- The operation creates no table, cache, file, proposal, feedback, rule, activation, or log entry containing description, amount, account, transaction, token, or private path.

### Failure Criteria

- Do not read live Ledger storage, reconstruct transfer/refund eligibility, persist normalized descriptions, or create rules from groups.
- Do not return raw source descriptions or transaction identities; only the owner-visible normalized representative and aggregate scope are allowed.

### Expected Outputs

- ClassificationUnresolvedStore, GetUnresolvedPatternReportQuery, and unresolved mapper

### Constraints

- Ledger is read-only through LedgerContractClient and the complete report is built before stdout serialization.
- The shipped classification_v1 contract is authoritative. A projection, query, lifecycle, or mutation-precondition gap blocks this CLASSIFY slice until an audited LEDGER-owned change and dependency exist.
