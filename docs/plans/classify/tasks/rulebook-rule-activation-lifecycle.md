## Recipe

### Acceptance Checks

- Require exact current validation evidence, zero incorrect canaries or unexplained conflicts, active category identity, and explicit owner actor/reason; atomically create immutable version, membership, event, and active pointer.
- Broad apply defaults false and is limited to the authorized validated version; failure preserves the prior pointer.
- Retire or replace through an attributable successor with retained history; category archive or identity change, stale evidence, and missing corpus block new authority; same-ID rename refreshes display.

### Failure Criteria

- Never mutate versions in place, activate automatically, grant broad apply from stale or missing evidence, or delete history.

### Expected Outputs

- Activate/retire commands, RuleSetStore, and RuleLifecyclePolicy

### Constraints

- Use explicit SQLite transactions and immutable attributable history.
