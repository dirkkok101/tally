## Recipe

### Acceptance Checks

- Supported active-category rule saves as an immutable draft; unsupported predicates and missing or archived categories create no activatable version.
- Passing current private evidence permits explicit activation; absent, stale, incorrect-canary, or unexplained-conflict evidence leaves the prior active set unchanged.
- Retirement and validated replacement create successor rule sets and preserve all prior versions and provenance.
- Category rename refreshes display, lifecycle changes invalidate authority, and no save, validation, feedback, or startup event activates automatically.
- Status and abandon preserve referenced history and remove only allowed unreferenced payload.

### Failure Criteria

- Do NOT omit private-corpus unavailable, incorrect-canary, conflict, category lifecycle, or no-auto-activation paths.
- Do NOT use tracked private rows or assert lifecycle only through database internals.
