## Recipe

### Acceptance Checks

- IngestMigrationV001.cs remains byte-for-byte unchanged; IngestMigrationV002.cs upgrades both a new version-0 database and an existing version-1 database to user_version 2 in ordered transactions.
- V002 creates one store-generation row, append-only batch_error_event with complete IngestError metadata and unique per-batch sequence, and metadata-only status_snapshot plus status_snapshot_item with immutable ordinal membership and cascade expiry cleanup.
- BatchErrorEventStore.AppendAsync writes the complete metadata-only error event in the caller-owned workflow transaction; LatestAsync returns the highest sequence without deriving missing guidance from error_code.
- Real SQLite tests prove constraints, foreign keys, owner protection, migration replay, V001 compatibility, error append/read order, snapshot immutability, and absence of prohibited payload columns.

### Failure Criteria

- Do NOT modify IngestMigrationV001.cs or rebuild/drop V001 tables — immutable migration rule per DD-INGEST-STATE-STORE.
- Do NOT persist source paths, statement rows, descriptions, amounts, balances, full identifiers, manifests, frozen requests, exceptions, or stack traces in error or snapshot tables.
- Do NOT make StatusHandler or BatchErrorEventStore infer category, mutation possibility, durable state, retry action, metadata-only message, or field from a partial code.

### Expected Outputs

- IngestMigrationV002 and version-2 migrator
- BatchErrorEventStore durable append/read primitive
- Protected ephemeral status snapshot schema

### Constraints

- Raw Microsoft.Data.Sqlite, snake_case SQL, foreign keys, WAL, synchronous FULL, explicit transactions, and CancellationToken propagation.
